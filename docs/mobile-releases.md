# 后台预览与移动端更新说明

## 边界与事实源

本规范描述 Android 更新前与升级后的一次性说明提醒，以及 Web 管理后台编辑与预览的可观察行为。App 移除独立“查看更新”按钮、独立说明／版本历史页面和设置／游客“我的”中的历史入口；已部署的 Backend 公开历史、详情 HTTP、历史数据、后台维护与发布门禁继续保留。本次不修改 HTTP Schema，不新增 iOS 发版或系统推送／FCM 事件。

更新前／升级后弹窗替代原横幅到详情、主动历史和“升级后不弹窗”的方案；原记录保留在 [兼容登记](deprecation-register.md#后台预览与移动端更新说明文档)。此修订是待 Mobile 接入和验收的展示规范，不代表新交互已上线，也不授权再次合并或发包。

HTTP 字段、内容校验、权限、确认记录、分页和发布事务由 [Backend API 契约](https://github.com/morenk/wenyousite-backend/blob/dev/docs/api-contract.md)拥有，该链接仅作事实源入口；消费者接入以治理交付的 Backend 精确提交为准。本规范不预编接口字段或复制 Schema，既有 `/meta` 字段及其升级策略语义保持兼容。

颜色、系统字体、排版层级、间距、触控、明暗模式和无障碍复用 [共享设计基础](foundation.md)、[反馈与浮层](interaction.md)、[呈现规则](presentation.md)及对应平台 profile，数值仍由 [机器契约](../contracts/foundation.v1.json)拥有。本次不增加 Token、公开导出、生成常量或包版本；消费者继续固定原已发布 Foundation Tag。

## 内容与版本身份

- 每份说明由人工编写的纯文本摘要和按作者顺序排列的纯文本条目组成。预览与移动端保持相同文字、条目边界和顺序，不解析 Markdown、HTML 或富文本，不从 Git 提交、构建信息或版本差异自动编造文案。
- 摘要用于快速了解变化；完整说明保留摘要和全部条目。条目自然换行，不用固定高度裁切长内容，也不将每条说明装进独立装饰卡片。可见文字中的链接样式或标记仍按纯文本呈现，下载使用独立操作入口。
- 每份说明精确对应平台、版本名和构建号。展示以版本名为主要识别信息，构建号作为可读辅助信息；多平台管理场景同时明确平台，不仅凭版本名匹配，不跨平台或跨构建复用另一份说明。
- 更新前弹窗按升级目标读取说明，升级后弹窗按设备实际安装版本读取说明；后台预览和缓存也必须保持该身份对应。切换目标或后到的旧响应不能把上一版本的说明附在新版本上，不能把旧说明与新下载目标混用，也不能用服务器最新说明冒充已安装版本说明。

## 后台状态与预览

后台使用“草稿、待发布、已发布”表达业务状态，并清楚区分正在编辑的内容与已确认内容；状态名称不代替内容确认结果。服务端状态转换和授权仍以 Backend 契约为准。

| 内容阶段 | 后台与用户侧的共同语义 |
| --- | --- |
| 草稿 | 普通管理员可编辑未发布草稿；预览明确标记草稿，只供管理检查，不出现在公开说明或历史中 |
| 待发布 | 超级管理员确认对应版本身份及完整说明后形成已确认快照；后台确认不触发发包，也不使该记录公开 |
| 已发布 | 真实版本晋级成功后公开对应已确认说明并进入历史；保存、确认或构建成功本身不能显示为已发布 |
| 编辑修正 | 草稿与已确认快照分开；已发布文案仅由超级管理员修正并重新确认，确认前用户继续看到旧的已确认快照 |

- 后台提供草稿预览和已确认内容的明确区分，预览头部显示所对应的平台、版本名、构建号及内容状态。超级管理员确认前必须能检查完整摘要和所有条目，不能用截断预览代替完整确认。
- 已确认的待发布说明发生编辑时，不能把未确认的新稿作为发版依据；界面保留原已确认内容，并明确新稿仍需确认。版本或确认记录在预检后变化时，发版流程必须停止并重新核验，不能悄悄改用新内容。
- 保存、确认或修正失败时保留输入，并在表单上下文反馈；冲突要求重新核对服务端内容，不能显示成功或用本地草稿替换已确认快照。提交中的控件遵循既有 pending 与重复提交规则。
- Windows 发版前必须预检已确认说明，晋级前再次核验版本身份及确认记录；缺失或变化即停止。既有 APK、签名与 hash 校验继续独立保留。晋级失败恢复旧策略，不提前公开待发布说明；重试遵循 Backend 幂等结果，不产生重复历史或虚假的发布成功。具体流程与校验实现归 Backend／Mobile。

## 更新前提醒

是否可更新、目标身份、推荐或强制状态以及下载操作均以既有 `/meta` 实际策略为准；说明、公开历史和本机提示记录不能自行产生或取消升级资格。更新前弹窗直接显示目标版本与构建号、人工摘要和全部条目，复用既有更新／下载动作，不再经“查看更新”跳转到独立详情。

| 类型 | 展示与一次性边界 |
| --- | --- |
| 推荐更新 | 每个目标平台与构建号自动提示一次；提供明确关闭入口，关闭或原生返回后可继续使用。旧实现已经保存的忽略记录继续有效，不因入口迁移、登录切换或文案修订重新提示同一目标 |
| 强制更新 | 使用不可关闭的阻断弹窗，可由既有启动门禁容器承载；直接展示完整说明和原更新动作，不新增独立说明页面。只要策略仍要求强制更新就持续阻断，不受推荐已提示、旧忽略或升级后已展示记录限制 |

- 推荐的“已提示”在同一目标的完整说明实际可见后持久记录；请求发出、排队、加载占位或错误态不能消耗该次机会。当前会话共享展示锁，冷启动、Widget／路由重建、后台返回和账号切换不能重复自动弹出已提示目标。已有忽略记录优先抑制推荐，并按原有身份与有效范围迁移，不把旧忽略扩大到其他构建。
- 推荐弹窗关闭后不自动打开其他说明页面；不以横幅、设置入口或游客入口保留被移除的查看模块。用户触发更新前重新核对有效目标；策略变化时刷新或退出失效提醒，不能继续使用旧目标的更新动作。说明文字不决定下载地址。
- 推荐升级为强制时立即服从强制策略；即使同一目标已提示或被忽略，也不能放行。强制弹窗的系统返回、遮罩点击、说明重试和失败均不能进入受限应用内容；后续启动未完成所需升级仍须阻断，重复策略通知只更新当前承载面，不堆叠弹窗。“一次”仅约束可关闭的推荐与升级后提醒。

## 升级后提醒

升级后提醒显示设备实际安装的平台、构建号及其对应版本名的已发布说明，包含人工摘要和完整条目。有可信旧构建且构建号上升时使用“已更新”；仅有首次迁移覆盖安装证据时使用“已安装当前版本”，不声称知道旧版本或证明构建号递增。弹窗可关闭，不提供对该已安装版本的再次更新／下载入口，也不进入历史页面。

| 安装观察结果 | 提示处理 |
| --- | --- |
| 无本机记录，Android 首次安装与最后更新时间均有效，且最后更新时间更晚 | 首次迁移可确认发生过覆盖安装，为当前实际安装版本建立待提示并显示一次说明；不推测旧构建号。同构建覆盖安装也可能触发这一次迁移提示，这不等于已证实版本升级 |
| 无本机记录，安装与更新时间相同，或证据缺失／无效／逆序 | 相同时间按首次安装处理，不弹升级后说明；证据不可用时也只保守建立当前安装基线，不依据账号登录、版本名或服务器最新版本猜测升级 |
| 同平台构建号上升 | 记录当前实际安装版本为待提示；应用可用后的首次合适启动展示其说明，一版一次，跨过多个版本也只展示本次安装版本 |
| 构建号不变 | 只恢复尚未成功展示的待提示；已展示的版本不因冷启动、重建、登录／退出或切换账号重新弹出 |
| 降级或平台变化 | 不作为升级，不补弹旧版本；重新建立对应安装基线，保留仍有意义的已展示记录，不将其他平台或构建的待提示套到当前安装版 |

- 本机安装基线、待提示和已展示记录相互独立，归本机安装使用，不按用户账号分开，也不随退出登录清除。一次提示身份为平台与构建号；文案修订号（revision）、版本名显示修正或重新确认说明不能让同一构建再次弹出。版本名仍须与实际安装包核对，不接受错配内容。
- 首次迁移先恢复可用的既有平台／构建记录，只有无本机记录时才使用 Android 安装时间兜底。一旦建立本地记录，同构建覆盖安装即使改变最后更新时间也不产生新的待提示；原有未成功展示的待提示仍可重试，已展示记录始终抑制重复。安装时间无法说明原构建号，不用于推断跨过了哪些版本。
- 更新安装基线不能顺带清除尚未展示的待提示。仅在正确版本的完整说明实际可见后持久记录“已展示”；后台取回、缓存命中、加载占位、错误态、被强制更新挡住或排队等待都不算展示，不要求用户逐条滚动确认后才记账。
- 待提示期间再次升级时，以新的实际安装版本替换待提示，只提示当前安装版，不补播中间版本。卸载或清除数据后若本机记录丢失，重新按上述首次迁移证据判定。Android 清除数据后可能保留系统安装／更新时间，无法与首次支持版的无本机记录可靠区分；不能声称可靠识别清数据、保证跨卸载／清数据去重，也不能将无记录一律视为新安装或升级。

## 提示优先级与串行规则

- 所有更新提醒由同一展示协调者控制，同时最多一个承载面。先核验既有启动与强制策略；强制更新优先，不在启动遮罩、登录切换过渡或不可用应用后面打开推荐／升级后弹窗。策略自身不可用时沿用原失败规则，不从说明或历史猜测可用性。
- 在应用已经可用、处于前台且没有其他阻断流程的首次合适时机，优先处理实际安装版本的升级后待提示；推荐择后处理。没有升级后待提示时，才直接评估有效且未提示／未忽略的推荐目标。
- 升级后提醒展示或本次失败尝试结束后，推荐只能在其关闭后的下一次安全前台机会重新评估，不能在关闭回调中立即接弹，也不能叠在升级后弹窗上。升级后读取失败不要求推荐无限等待成功；保留待重试状态，本次前台会话不自动循环尝试。
- 提醒排队期间再次核验实际安装身份、最新策略及已提示／忽略记录。强制状态到来时先撤下低优先级提醒，再接管阻断；尚未真正展示的升级后说明仍待处理，已真正展示的不再重弹。新推荐目标不能把正在显示的已安装版本说明替换成另一份内容。
- 弹窗结束后恢复原任务与可用焦点。App 不保留独立说明／历史页面、设置或游客历史入口；旧页面地址按平台既有安全回退返回可用入口，不留下失效按钮、空壳页面或隐蔽的历史入口。

## 读取失败与恢复

- 区分加载中、确认没有记录、读取失败和已有内容刷新失败。加载失败保留“更新说明加载失败”等上下文提示及“重试”入口，不能显示成“暂无更新”“没有变化”，也不能据此伪造摘要、条目或展示成功。
- 推荐与升级后说明失败都不阻断普通启动；错误态可关闭，关闭后本次前台会话不循环弹出，未成功展示的说明保留后续合适启动重试资格。重试在当前说明上下文或后续受协调的提醒中进行，不重建独立历史模块；已有忽略记录继续优先抑制推荐。
- 强制更新的说明失败时保留目标身份、既有可用更新动作及重试入口，持续执行原阻断策略，不因“一次提醒已用完”、说明为空或失败而放行。推荐说明失败也不能禁用本来有效的更新动作。
- 只有服务端明确没有对应已发布记录时才显示“此版本暂无更新说明”；旧版缺失不自动生成历史或文案。没有完整说明不记为已展示，不频繁自动重试，不把错误或无记录提示当作新版内容。
- 刷新失败可保留同一身份的已确认内容并提示刷新失败；目标或实际安装身份变化后不得保留另一版本内容。旧请求不能覆盖新目标、恢复失效更新动作，或给错误构建写入已提示／已展示记录。

## 跨端呈现与验收

Web 后台保留紧凑表单与工作台密度；草稿和已确认内容的预览采用相同内容层级，移动宽度预览只用于检查更新前／升级后完整摘要、条目与换行，不要求后台采用移动布局。Mobile 保留单列、系统文字缩放、安全区、原生返回和既有触控下限。具体平台差异见 [Web profile](platforms/web.md#移动端更新说明管理与预览)和 [Flutter profile](platforms/mobile.md#更新前与升级后提醒)。

- 标题、正文、版本元数据和按钮复用既有语义排版，明暗主题下保持相同顺序和可读性；长摘要、长条目与长版本名自然换行，不能压缩触区或遮挡操作。
- 更新前目标与升级后实际安装版本使用明确文字及读屏语义区分，不仅靠颜色；读屏顺序与可见摘要、条目顺序一致。Web 验证键盘访问与焦点返回，Mobile 验证大字体下滚动、关闭、重试和更新操作可达。
- Mobile 验收覆盖独立按钮／页面／设置与游客入口移除、旧地址安全回退、推荐每目标一次与旧忽略兼容、同目标由推荐变为强制、跨冷启动／重建／账号切换去重、跨多版只提示实际安装版、降级、revision 修订不重弹及加载失败不误记展示。首次迁移分别验证无记录的覆盖安装、同构建覆盖安装、首次安装时间相同、时间缺失／无效／逆序，以及建立本地记录后同构建重装不重弹。进一步验证强制抢占、升级后优先、推荐顺延、无叠窗，以及请求返回前目标／安装身份变化。
- Backend／Web 原有草稿与确认快照隔离、已发布修正确认前后、版本身份冲突、预检后内容变化、晋级失败及幂等重试仍按既有门禁验收；App 入口移除不构成删除 Backend 历史／详情接口、旧客户端兼容或历史数据的依据。新增提醒不产生新的系统通知、FCM 推送或通知中心事件。
- Web 后台预览与 Mobile 界面提供明暗、窄屏及长内容实际画面，并标记“候选／待验收”；截图、交互测试及负责人验收由各消费者任务交付。本仓库文档检查不能替代界面、真机、发版流程或隔离 E2E 验收。任何写入测试仍须遵循治理隔离规则。
