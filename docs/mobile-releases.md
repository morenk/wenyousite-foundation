# 后台预览与移动端更新说明

## 边界与事实源

本规范描述 Android 用户更新前阅读说明、主动查询版本历史，以及 Web 管理后台编辑与预览的可观察行为。它是待消费者接入和验收的展示规范，不表示接口、客户端或正式版本已经上线；不新增 iOS 发版、升级后自动弹窗或系统推送／FCM 事件。

HTTP 字段、内容校验、权限、确认记录、分页和发布事务由 [Backend API 契约](https://github.com/morenk/wenyousite-backend/blob/dev/docs/api-contract.md)拥有，该链接仅作事实源入口；消费者接入以治理交付的 Backend 精确提交为准。本规范不预编接口字段或复制 Schema，既有 `/meta` 字段及其升级策略语义保持兼容。

颜色、系统字体、排版层级、间距、触控、明暗模式和无障碍复用 [共享设计基础](foundation.md)、[反馈与浮层](interaction.md)、[呈现规则](presentation.md)及对应平台 profile，数值仍由 [机器契约](../contracts/foundation.v1.json)拥有。本次不增加 Token、公开导出、生成常量或包版本；消费者继续固定原已发布 Foundation Tag。

## 内容与版本身份

- 每份说明由人工编写的纯文本摘要和按作者顺序排列的纯文本条目组成。预览与移动端保持相同文字、条目边界和顺序，不解析 Markdown、HTML 或富文本，不从 Git 提交、构建信息或版本差异自动编造文案。
- 摘要用于快速了解变化；完整说明保留摘要和全部条目。条目自然换行，不用固定高度裁切长内容，也不将每条说明装进独立装饰卡片。可见文字中的链接样式或标记仍按纯文本呈现，下载使用独立操作入口。
- 每份说明精确对应平台、版本名和构建号。展示以版本名为主要识别信息，构建号作为可读辅助信息；多平台管理场景同时明确平台，不仅凭版本名匹配，不跨平台或跨构建复用另一份说明。
- 详情、后台预览、历史和缓存必须保持该身份对应。切换目标或后到的旧响应不能把上一版本的说明附在新版本上，也不能把旧说明与新下载目标混用。

## 后台状态与预览

后台使用“草稿、待发布、已发布”表达业务状态，并清楚区分正在编辑的内容与已确认内容；状态名称不代替内容确认结果。服务端状态转换和授权仍以 Backend 契约为准。

| 内容阶段 | 后台与用户侧的共同语义 |
| --- | --- |
| 草稿 | 普通管理员可编辑未发布草稿；预览明确标记草稿，只供管理检查，不出现在公开说明或历史中 |
| 待发布 | 超级管理员确认对应版本身份及完整说明后形成已确认快照；后台确认不触发发包，也不使该记录公开 |
| 已发布 | 真实版本晋级成功后公开对应已确认说明并进入历史；保存、确认或构建成功本身不能显示为已发布 |
| 编辑修正 | 草稿与已确认快照分开；已发布文案仅由超级管理员修正并重新确认，确认前用户继续看到旧的已确认快照 |

- 后台提供草稿预览和已确认内容的明确区分，预览头部显示所对应的平台、版本名、构建号及内容状态。超级管理员确认前必须能检查完整摘要和所有条目，不能只确认横幅截断预览。
- 已确认的待发布说明发生编辑时，不能把未确认的新稿作为发版依据；界面保留原已确认内容，并明确新稿仍需确认。版本或确认记录在预检后变化时，发版流程必须停止并重新核验，不能悄悄改用新内容。
- 保存、确认或修正失败时保留输入，并在表单上下文反馈；冲突要求重新核对服务端内容，不能显示成功或用本地草稿替换已确认快照。提交中的控件遵循既有 pending 与重复提交规则。
- Windows 发版前必须预检已确认说明，晋级前再次核验版本身份及确认记录；缺失或变化即停止。既有 APK、签名与 hash 校验继续独立保留。晋级失败恢复旧策略，不提前公开待发布说明；重试遵循 Backend 幂等结果，不产生重复历史或虚假的发布成功。具体流程与校验实现归 Backend／Mobile。

## 更新入口与完整说明

更新说明辅助用户理解更新；是否可更新、目标身份、推荐或强制状态以及下载操作均以既有 `/meta` 实际策略为准。历史记录或说明请求不能自行产生升级资格。

| 入口 | 展示与交互 |
| --- | --- |
| 推荐更新横幅 | 显示目标版本和摘要，提供“查看更新”进入完整说明与下载入口；保持非阻断，不抢占启动、当前任务或焦点，用户可继续使用应用 |
| 更新详情 | 展示目标版本、摘要和全部条目；仅当此记录仍是 `/meta` 对当前安装版的实际可更新目标时，提供更新／下载操作；返回原入口并保留阅读上下文 |
| 强制更新页 | 直接展示目标版本、摘要和全部条目，长内容可滚动，更新操作保持可达；保留既有强制更新约束，关闭说明、系统返回或重试均不能进入受限应用内容 |

- 横幅可以使用既有紧凑摘要预览；完整内容在详情可读，不以 Toast、Tooltip 或只显示变更数量代替说明。推荐更新不因说明加载而升级成阻断弹窗。
- 用户触发更新前重新核对有效目标；策略已变化时刷新目标与说明，不能继续提供旧记录的更新操作。说明中的文字不决定下载地址。
- 安装新版后不自动打开“更新了什么”弹窗；用户可以主动进入版本历史阅读。新增说明不产生新的系统通知、FCM 推送或通知中心事件。

## 主动查询版本历史

- 登录用户从设置的“更新说明”进入，游客从“我的”同名入口也可进入同一公开历史，无需登录；页面内以“版本历史”描述列表，不增加主导航目的地，不依赖当前有可用更新才提供入口。
- 历史只包含当前平台已发布的记录，按 Backend 返回的版本历史倒序展示并使用其游标继续加载，不按版本名字典序重排，不暴露草稿或待发布内容。
- 列表以版本身份和摘要供扫描，进入后可读完整内容；已加载页面和滚动位置按既有导航规则恢复，加载更多保留已读内容。
- 与当前安装的平台、版本名、构建号精确一致的记录标记“当前版本”；该标记指当前安装版本，不是服务器最新版本。已安装旧版没有记录时，不把最新记录标为当前版本，也不伪造一条历史。
- 没有已发布记录时显示“暂无版本历史”；已明确没有当前旧版说明时显示“此版本暂无更新说明”。空态不等于版本没有变化，不伪造日期、摘要或条目，不用 Git 自动回填旧历史。
- 旧历史记录可以阅读；更新／下载操作仍只对 `/meta` 认定的实际可更新目标开放，不把每条历史变成降级或重新安装入口。已是当前版或没有可更新目标时不提供虚假的更新动作。

## 读取失败与恢复

- 区分加载中、确认没有记录、读取失败和已有内容刷新失败。加载失败保留“更新说明加载失败”等上下文提示及“重试”入口，不能显示成“暂无更新”“没有变化”或空历史。
- 说明读取失败不阻断普通启动和推荐更新下的正常使用，也不改变 `/meta` 已确定的强制更新约束。强制页保留目标身份、既有可用更新操作和说明重试入口，不因说明为空而放行；升级策略自身不可用时继续遵循原策略失败规则，不能从历史推断替代策略。
- 刷新失败可保留同一身份的已确认内容并标记刷新失败；目标变化后不得保留另一版本的内容。首次加载及重试只影响对应说明区域，不用整页等待替换仍可阅读的内容。
- 历史续页失败保留已加载记录，并在列表末尾提供重试；旧请求不能覆盖新目标、新内容或恢复已经失效的更新动作。

## 跨端呈现与验收

Web 后台保留紧凑表单与工作台密度；草稿和已确认内容的预览采用相同内容层级，移动宽度预览只用于检查换行及条目，不要求后台采用移动布局。Mobile 保留单列、系统文字缩放、安全区、原生返回和既有触控下限。具体平台差异见 [Web profile](platforms/web.md#移动端更新说明管理与预览)和 [Flutter profile](platforms/mobile.md#更新说明与版本历史)。

- 标题、正文、版本元数据和按钮复用既有语义排版，明暗主题下保持相同顺序和可读性；长摘要、长条目与长版本名自然换行，不能压缩触区或遮挡操作。
- 状态和“当前版本”使用可见文字及读屏语义，不仅靠颜色区分；读屏顺序与可见摘要、条目顺序一致。Web 验证键盘访问与焦点返回，Mobile 验证大字体下滚动、返回和更新操作可达。
- 消费者验收覆盖草稿／确认快照隔离、已发布修正确认前后、版本身份冲突、预检后内容变化、晋级失败及幂等重试、推荐横幅到详情、强制页、设置与游客入口、当前版本标记、旧版空态、首载／刷新／续页失败和目标切换后的旧响应。
- Web 后台预览与 Mobile 界面提供明暗、窄屏及长内容实际画面，并标记“候选／待验收”；截图、交互测试及负责人验收由各消费者任务交付。本仓库文档检查不能替代界面、真机、发版流程或隔离 E2E 验收。任何写入测试仍须遵循治理隔离规则。
