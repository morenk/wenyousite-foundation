# 主题帖文字颜色

机器事实源为 `contracts/foundation.v1.json` 的 `experiences.editor.textColor` 与 `experiences.elements.inline.textColor`。Web 消费 `@wenyousite/foundation/editor` 的 `EDITOR_TEXT_COLOR_PROFILE`、`EDITOR_TEXT_COLOR_PRESETS`，Flutter 消费 `WenyouEditorTextColorContract`；本文不另外定义预设数值或业务 DTO。

## 适用范围与呈现

主题正文、子帖正文、楼层和回复共享文字颜色；动态、私信和主题标题不开放。颜色为不透明 RGB，作者指定的原值在阅读态、编辑态、明暗主题、草稿和富文本剪贴板中一致保留，不自动调整，不提示对比度不足。该规则只适用于作者正文，应用控件和默认正文继续遵守现有主题与对比度规则。

显式文字色优先于普通链接和行内代码的默认前景色，链接下划线、行内代码背景、字号、字重及其他格式保留。恢复“默认”只移除颜色标记，重新继承各元素自己的前景色。图片、骰子、提及、传送门等原子节点不着色；不能让外层颜色继承覆盖它们的既有视觉与身份语义。

## App 交互

- 主工具栏不增加独立按钮。“正文样式 T”内展示默认、机器契约中的五个预设、最多四个最近自定义色与“自定义”。最近色只记录已应用的自定义 RGB，按账号保存在本机，规范化去重并按最近使用排序。
- 只有有效文字选区可执行颜色操作；跨段范围拆成各行内区间，跳过原子节点。混合选区不误选某个色块，没有选区时禁用。此次操作不使之后新输入自动继承颜色。
- 默认、预设与最近色点选即应用并收起；打开“自定义”时保存正文选区并收起正文键盘，在同一工具区域替换为拖动取色、R/G/B 整数输入和文字预览，不叠加独立弹窗。
- 调色只更新面板预览，“应用”提交一次格式事务，取消保留原文。一次撤销还原整次变更；应用或取消后恢复正文焦点和原选区。数字输入使用数字键盘，取色区按可用高度滚动，适应半屏编辑器。
- 控件满足移动端最小触控尺寸；色块提供可读名称与选中语义，拖动取色同时提供可访问的 RGB 输入。保留必要字段标签、错误与恢复操作，不增加常驻说明、成功弹窗或对比度告警。

## Web 与协议边界

Web 首期提供既有颜色的显示、编辑保源、草稿与复制粘贴，工具栏不开放取色。Milkdown 解析、编辑事务与序列化不能丢失颜色；正文往返检查必须比较颜色，转换失败阻止保存并保留编辑现场。

正文协议、受控标记、能力声明、旧端读取降级、缓存区分和旧端覆盖保护由 Backend 的独立文本颜色 v1 契约拥有。只接受其受控 `span`，不因此开放任意 HTML、CSS 或未知属性；颜色外层与粗斜删、普通链接及行内代码的组合、物理行范围和原子排除以固定后端语料为准。不提升全局 Markdown 版本，不替代角色提及能力。合法协议的纯文本复制与摘要只保留文字，不泄漏隐藏标记。

## 已提交协议来源

[Backend 文本颜色 v1](https://github.com/morenk/wenyousite-backend/blob/1bc1986a936131cdacf259c0fd9443be0de1f026/docs/markdown-text-color-v1.md)拥有精确协议；[固定颜色语料](../contracts/fixtures/markdown-text-color-v1-fixtures.json)、[节点 Schema](../contracts/fixtures/markdown-text-color-v1.schema.json)与[剪贴板 v2](../contracts/fixtures/editor-clipboard-v2-fixtures.json)按该提交原字节同步，来源及 SHA-256 记录于 [text-color-source.json](../contracts/fixtures/text-color-source.json)。

合法颜色只包裹单个物理行内的平衡格式；H2/H3、引用和列表前缀位于颜色外。旧端去色须保留文字语义并重新转义可能变成块语法的字面标点，不能简单删除标签再解释。Mobile 本机结构化剪贴板保色，系统剪贴板继续纯文本互操作；Web 只识别本站 envelope 的受控颜色属性，外部 HTML/CSS 仍按既有纯文本策略处理。

此镜像不定义 HTTP Schema，也不代表后端已合并或部署；消费者应在服务端能力确认后开放入口，新写关闭仍需读取保源和旧端覆盖保护。

## 验收与发布

共享检查覆盖 Schema 反向用例、预设和导出同源、现有主栏不扩张、Web 无创建入口、原值呈现及原子排除。消费者另验选区、取消、默认、单步撤销／重做、RGB 边界、混合颜色、跨段、中文输入法、emoji、组合格式、草稿和 App → Web → App 往返，不能将 Foundation 常量检查代替实际编辑与视觉验收。

视觉候选须提供 320/360dp、明暗、大字号和键盘状态画面；自动化真实环境只读，写入 E2E 使用本轮核验的隔离资源并记录清理结果。

本次提交保留既有包、契约和 Manifest 版本，新增能力建议后续以 `7.4.0` 发布，版本须由负责人明确决定。合并、版本提升、正式 Tag／Release 分别遵守仓库门禁；消费者只能在正式发布后独立锁定 Tag，不消费候选提交或复制常量绕过发布。发布顺序为兼容后端 → 可读保源消费者 → 开启新写。回退消费者不删除存储中的颜色；旧端兼容和覆盖保护继续保留，后续清理另开 PR。
