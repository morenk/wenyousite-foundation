# 动态主题正文字体

本文固定 Backend `62a0313a75c85e42dfa39cd09b7cc90ae5c34186`（API `5.43.0-dev.20261022.3`）的[动态字体契约](https://github.com/morenk/wenyousite-backend/blob/62a0313a75c85e42dfa39cd09b7cc90ae5c34186/docs/dynamic-text-fonts.md)与 [OpenAPI](https://github.com/morenk/wenyousite-backend/blob/62a0313a75c85e42dfa39cd09b7cc90ae5c34186/contracts/openapi.json)。七份原字节镜像、审计枚举投影及文档／OpenAPI 等引用摘要见[来源记录](../tests/fixtures/text-font-dynamic/source.json)。Backend 唯一拥有协议、业务目录与资源，Foundation 不建立另一套运行时目录或版本 ID 白名单。

该提交已实现数据库版本、独立 Worker、私有资源网关及历史导入，动态入口不再是固定 503 占位。未配置私有 bucket 或沙箱目录时仍返回 `503/50301`；新写默认关闭，v2 支持及新写按完整导入、资源校验和配置门禁计算。公共环境尚未部署，两端真实联合同会话验收仍待 Android，不能把代码交付或后端测试通过等同于已经上线。

[既有规范](thread-fonts.md)固定的正文 v1 与运行策略 v2 继续作为兼容依据。该运行策略 v2 的固定 28 款快照，与新增动态正文协议是不同概念；不能因为版本名称相似而拼接策略。现有原字节测试镜像不覆盖、不改义。以下动态行为适用于完成新协议接入的消费者。只有本会话尚未激活 v2 且无已知撤回墓碑时，才可继续原 v1 路径；首次确认支持后不得因能力缺失或失败切回旧路径。

## 版本身份与正文

管理员发布客户端构建后才创建的字体版本，Web 与 Mobile 应在同一会话获得并使用，无需逐款改代码、重新构建或安装 APK。家族用于组织和选择；正文绑定不可变版本身份，不绑定名称、排序、当前目录位置或“最新版”。第二版发布及目录回滚只影响后续选择，不能让旧帖、草稿或历史复制源自动换成另一版。

正文使用 `data-wenyou-font-v2`，值为 `^tfv_[a-f0-9]{32}$`；版本在处理成功时创建。`tff_` 家族 ID 不可写入正文。读取声明 `X-Text-Font-Version: 2`，所有正文写入 DTO 声明 `textFontVersion: 2`，包括删光字体；能力 2 包含 v1／v2 混合正文。同一 span 只能有一种字体属性，可合并颜色 v1，规范顺序为字体、颜色。颜色与角色提及继续独立协商。

`/meta.capabilities.textFontV2Supported` 仅在私有状态网关就绪、固定映射的 28 个版本全部完成导入并有发布记录后为 true；之后停用或撤回不降低这项就绪状态。`textFontV2WriteEnabled` 还要求新写开关开启，缺失均按 false。未就绪时正文保源与降级协议仍有效，不能把解析能力当成旧资源通道切换许可。旧 v1 客户端仅保留 v1、移除 v2；无字体能力移除两版，均为安全展示副本。新或原正文含 v2 而写入方未声明 2 时返回 `409/40019`，拒绝覆盖。未知、停用或撤回版本的已有范围可原样保留、重排或移除，禁止新增／重复／扩写，禁止的新写返回 `409/40020`。服务端去重批量查询身份，并在正文事务内与状态变更按共同锁序复核；不能以一次客户端检查替代最终准入。

客户端不将版本 ID 编译为枚举，不以当前目录包含与否决定历史内容是否可解析；格式不合法与语法合法但尚未知的版本须分开处理。未知版本的原文字、身份及其他合法格式保留，显示先回退系统字体并按需解析身份；无法保源时阻止有损覆盖，不能静默移除标记再保存。旧端读取使用兼容投影，写入保护须覆盖创建、编辑、草稿和聚合保存等实际入口。

28 款历史字体可通过可重跑导入建立固定映射，重复导入不另造历史身份、不改写 v1 资源与旧帖。小城继续退役，不通过导入或旧缓存恢复为可选项。未知或撤回内容的保源，不授予新选、下载或渲染权限。

UI、标题以及列表、搜索、消息、动态和分享摘要使用默认字体，零自定义字体下载／注册；已有缓存也不应用于这些场景。主题正文与编辑的局部选择、颜色和粗斜删、链接、撤销、输入法及阅读锚点仍遵循共享体验。

## v1 映射与同会话防降级

本会话首次确认 `textFontV2Supported=true` 后，28 款已映射 v1 ID 一律通过[固定导入映射](../tests/fixtures/text-font-dynamic/thread-font-v1-import-map.json)查询 v2 单版本描述符，并通过其本站状态网关获取资源。正文继续保留原 v1 标记和固定版本，不改成家族当前版本。后续 capability 为 false、缺失、错误或旧响应都不撤销本会话激活；单独关闭新写也不停止历史读取与状态再验证。未映射的退役小城保源、默认字体显示，不重启旧资源下载。

没有可信状态时，未知、404 或网络错误静默使用系统字体；不能回退旧 manifest、旧公共 URL 或仅凭磁盘字节恢复字体。404 负缓存仍为 30 秒。临时失败或 404 不抹除最近可信的 published／disabled 状态，可以按该状态使用已有缓存；恢复后经有效较新描述符更新非墓碑状态。已知撤回墓碑永远优先，迟到 published、旧修订、离线数据及 capability 降级均不能复活它，即使本会话尚未激活 v2 也不能借旧通道绕过已知墓碑。

上述状态同时控制 v1／v2 标记及已注册字形的使用。disabled 保留历史呈现、禁止新选／粘贴；withdrawn 停止两种标记的呈现与下载，保留原文并切换系统字体。SHA 与 family 相同不豁免状态检查，停止呈现不清注册账本、不声称卸载。Backend 对已导入旧 v1 ID 的新增范围同样按固定版本状态在正文事务内复核；历史范围仍可保留、重排或移除。

**旧客户端限制**：仅实现 v1 的二进制仍可能访问已发布公共 URL、缓存或已加载字形；v2 网关撤回不能收回这些字节，也不能立即关闭旧 CDN 路径。本次不删除旧资源或协议，不宣称历史 v1 客户端已经统一撤回。先完成并验证 28 款导入发布，再宣告支持并切换具备映射和防降级行为的消费者。

## 状态与粘贴

下表依据 `FontVersionDescriptorDto` 与生产者状态夹具；选择、粘贴和渲染必须分别判定。撤回是不可逆墓碑，不能由目录回滚解除。

| 状态或动作 | 新选与本次粘贴片段 | 已有正文与草稿 |
| --- | --- | --- |
| 当前启用版本 | `selectable`／`pasteAllowed`／`renderAllowed` 全为 true，可选择和粘贴；未下载不等于未知。 | 按需取得相同版本，资源到达前保源回退。 |
| 启用家族的历史已发布版本 | `selectable=false`，`pasteAllowed=true`；不能新选，但可粘贴原版本，不换为当前新版。 | `renderAllowed=true`，继续绑定原版本。 |
| 停用 | `selectable=false`、`pasteAllowed=false`、`renderAllowed=true`；粘贴片段去字体，保留受支持格式。 | 停用本身不撤回历史渲染许可；仍绑定原版本，不能升级或清理标记。 |
| 撤回 | 三个布尔值全为 false，资源引用为 null；禁止新选、下载和渲染，粘贴片段去字体。 | 保源并显示系统字体；缓存、已注册 face、迟到下载或旧目录都不能恢复渲染许可。 |
| 语法合法但身份未知 | 未确认获准前不引入本次粘贴内容，片段去字体。 | 保留身份和文字，合并按版本查询；查询失败不改写源内容。 |
| 目录回滚 | 后续选择按回滚后的有效目录执行，仍服从停用／撤回状态。 | 不改已保存版本，不将旧目录当成撤回解除。 |

过滤只发生在本次粘贴片段入口：保留目标支持的颜色、粗体、链接等格式，以及片段中其他仍获准使用的字体。不得把该过滤放进共用正文解码、编辑回填或草稿恢复。动态等不支持字体的目标去全部字体。Mobile 系统剪贴板仍按既有纯文本边界处理；只有已验证的受支持结构化路径才恢复格式。按描述符三个独立权限和写入能力执行，不用 `selectable` 代替 `pasteAllowed` 或 `renderAllowed`；历史非当前版本仍可粘贴，停用／撤回／未知片段去字体，原帖保源不受片段过滤影响。

## 同会话发现与恢复

轻目录只用于发现与选择，缩略样张不要求加载全部字体。每个版本的描述符、分片清单及实际字符资源按需获取，不因目录扩充、打开选择器或最近使用而预下载全集。发现结果按不可变版本引用内容哈希资源，不能覆盖旧哈希路径。

以下路由均在 API `/api/v1` 前缀下。`GET /meta/text-fonts/v2` 默认 `limit=100`，范围 1–200；这是最多项数，还须将完整成功信封的 UTF-8 JSON 限制在 65,536 字节。少于 limit 也必须跟随 `nextCursor`，不能以页长判断结束。首次请求确定 `releaseId`／`revision`，游标绑定发布、偏移和 limit；发布、停用或撤回使旧游标返回 `409/40927`。此时丢弃未完成的新快照，从第一页重取，保留完整旧快照且不混页；旧响应不能覆盖单调递增的新修订或已知撤回。

目录与 `GET /meta/text-fonts/v2/versions/:versionId` 描述符均为 `Cache-Control: no-cache`，按 ETag 再验证；304 无正文但服务端仍先读取当前状态。每 300,000 毫秒及前台恢复、选择器打开触发再验证，未知版本按 endpoint＋versionId 合并点查；404 负缓存 30,000 毫秒，暂时错误静默重试并保留最后可信值。已发布但非当前、停用版本返回描述符；未知或未发布为 404，撤回为 200 墓碑，三项权限 false、资源引用 null。不能把目录缺项、负缓存或请求失败当作删除历史正文的理由。

失败时继续使用最后一次验证通过且仍获准的结果，正文立即可读，重试静默进行。已经明确获知的撤回优先于旧目录、离线缓存及迟到结果；离线且尚未获知的服务端变化不能声称已经同步。目录版本变化不清空网络窗口、退避、Retry-After、资源隔离或原生尝试记录。既有慢链路进度超时、取消、请求合并、元数据限长及窗口恢复须由新策略明确承接，不能仅因目录变大而放宽。

## 动态资源账本

动态端点 `GET /meta/text-fonts/v2/runtime-policy` 使用 `policyVersion=3,fontVersion=2`，以[策略 JSON](../tests/fixtures/text-font-dynamic/thread-font-runtime-policy-v3.json)及[严格 Schema](../tests/fixtures/text-font-dynamic/thread-font-runtime-policy-v3.schema.json)为准。它不绑定全目录 manifest、不含固定家族数或固定注册快照；旧 `/meta/text-fonts/runtime-policy` 继续提供绑定固定 manifest 的 v2。Schema 校验、模式识别与本地范围校验均通过后才启用动态策略，不能混用形状或把发现失败当作无限额度。

网络沿用 60 秒滚动窗口：Web 最多 64 请求／16 MiB／并发 2，Mobile 最多 64 请求／24 MiB／并发 1。从实际开始计时，合法非空块刷新 15 秒 idle，10 分钟总截止固定；到达截止先拒绝迟到数据，排队不计时。完整预占、失败／取消不立即退款、full-jitter 与 Retry-After 等规则承接[既有持续加载规范](thread-fonts.md#持续加载与资源生命周期)，元数据、样张、manifest、notices 与字体请求全部记账。

Web 不以固定家族数量阻断后续阅读，仍以可见 lease 管理活动资源，维持 64 faces／16 MiB SFNT 输入估算边界。仅实际解除无引用资源的持有后归还相应驻留额度；不同家族与版本共享相同账本，目录更新不另开额度。输入估算不是浏览器 RSS 上限，需重复浏览实测。

Mobile 改为同一 FlutterEngine 内持续追加的注册账本，以 SHA＋family 去重；累计输入最多 64 MiB、最多 1,024 个键，包含失败的原生尝试，服务端只能收紧本地上限。原生调用前记账，成功复用、失败隔离，路由、目录、版本刷新和磁盘淘汰不清零；同 SHA 的不同 family 仍分别承担注册成本，不能生成别名绕过去重。达到上限时静默使用默认字体并保源，无弹窗要求重启，无假卸载；该有限账本不承诺无限次原生加载。下载失败而尚未调用引擎与原生调用失败须分别处理。

64 MiB 输入是累计原生注册输入的边界，不是 RSS、下载窗口或磁盘缓存大小。64 MiB 磁盘缓存独立计账；淘汰文件不释放注册账本。旧固定快照的 256 MiB 接受边界不能用于新的追加模式。需要在同一引擎跨目录／版本反复浏览，分别提供输入、注册键、失败占用、下载缓冲及实际内存走势。

## 单版本清单与资产授权

`GET /meta/text-fonts/v2/versions/:versionId/assets/:asset` 是本站状态网关，`:asset` 为 `sha256.format`，必须属于该版本已验证清单。描述符中的 `assetBasePath` 只能解析本站网关，不接受外链或任意文件路径。内容哈希不变不代表授权永久有效：资源响应为 `no-cache`，撤回返回 `410/41001`，不能公开可绕过状态校验的存储地址。客户端已知撤回后立即停止下载／呈现，迟到数据和已注册 face 不再使用；这不声称收回已经交付的字节。

[manifest v2 Schema](../tests/fixtures/text-font-dynamic/thread-font-manifest-v2.schema.json)描述单个不可变构建，不含可撤销状态。清单为原始 JSON，无 API 信封，完整文件最多 4,194,304 字节；按描述符的 bytes 预占，不套用未知元数据的 64 KiB 额度。目录、描述符、策略信封均限 64 KiB。清单、每个资源的实际字节、SHA、角色对应格式和状态许可须分别验证，不能只信 Content-Length 或 Schema 通过。

每片提供 Web WOFF2 和 Mobile SFNT（TTF／OTF），真实覆盖区间递增、不重叠且为 Unicode 标量，片间不重叠，分片并集等于 coverage，计数一致，shard id／family 唯一；缺字不能冒称覆盖。`web.format=woff2`、`mobile.format=ttf|otf`、`specimen.format=png`、`notices.format=json` 须做语义校验：当前通用 asset Schema 的格式枚举本身不能证明角色正确，也不能证明范围并集或实际字形。动态 family 来自清单，不使用展示名。基础样式为 400／normal，可变字体先固定默认轴；完整许可和来源随 notices 验证并保留。

## 管理与发布体验

以下描述本页固定的既有手工上传契约；[三字段上传与列表管理](thread-font-admin.md)另固定 Backend 1ce559b4 的新增管理员契约，源上传带 submissionId 时走新路径，旧手工入口与材料要求保留。该 pin 补充任务准确绑定提交的恢复字段，属于契约交接；运行实现与 E2E 仍须独立验收。

管理员上传单个 TTF／OTF 并填写名称、语言、排序、作者、来源及授权材料，预览处理结果后发布。上传上限为 64 MiB，不接受 ZIP、TTC、彩色字体或 URL 抓取；可变字体允许固定默认实例。分发、转码及分片权限不足时停留草稿，不进入处理或发布。状态展示应准确区分待处理、处理中、失败、待发布与已发布，不能把缩略图生成成功等同于字库可用。

私有暂存、持久任务与独立 Worker 由 Backend 实现；解析使用无网、非 root 隔离环境，按契约使用单并发、10 分钟和 2 GiB 资源边界。源 SHA、处理参数和工具链共同决定去重，重试不重复发布或覆盖旧对象。生成覆盖信息、许可声明、缩略样张及两端资源时保留必要排版字形；处理成功后仍须验证发布资源可读，才能原子发布目录。管理权限、紧急撤回的加强验证、CSRF 和审计复用既有机制，预览不触发公开发布，不自动清理历史产物。

管理端 `/admin/text-fonts` 复用管理员 Cookie、ADMIN／SUPER_ADMIN、写操作 CSRF，撤回额外 AdminStepUp。配置与源上传绑定 `expectedFamilyRevision` 和当次配置快照；处理前验证三项权限，不足返回 `409/40929` 并保留 draft。发布／启停需复核家族及目录修订，撤回需目录修订及原因，CAS 冲突 `409/40928`；回滚用发布入口选较旧版本。源、配置和工具链确定 buildKey，ready 不等于已发布，失败只返回固定 failureCode。具体请求 DTO 直接读取上述 OpenAPI，不在 Foundation 重定义。

## 管理审计与运行门禁

OpenAPI 的审计列表、导出筛选及 `AdminAuditLogResponseDto` 已包含以下动作，目标类型为 `TEXT_FONT`。管理端须能筛选、显示和导出这些记录，不能将它们落入未知类型或因仅支持旧枚举而丢失；具体权限、目标 ID 和记录内容继续按 Backend DTO 执行。

## 检查与运行交接

`pnpm test:text-font` 同时执行旧协议与动态协议测试。新组验证七份镜像的来源／字节完整性、导入表外身份、非法解析结果、混合能力与写入预期、三个状态权限、映射路由／能力降级预期、目录／缓存数值、v3 严格形状和全部可收紧范围的边界、账本预期、manifest 结构、历史导入映射及审计枚举投影一致性。保留旧 v1 与固定快照运行策略 v2 的独立测试，不以动态目录覆盖旧资源依据。

Schema 结构测试中的合成清单不代表真实构建产物；范围语义、角色格式、流式限长、事务锁、资源状态网关、原生注册与 Markdown 解析器均需生产者／消费者运行验证。本仓没有将静态语料做成模拟成功的加载器，API 哈希登记也不等于调用了运行路由。

治理交接记录：固定 Backend 提交的 `pnpm check` 通过 2,966 tests／219 suites，完整隔离 E2E `e2e_084b5262458cf5b259dd3e60` 通过且完成清理核验。此为 Backend／治理提供的执行结果，Foundation 本轮只核对已提交来源与契约，不重复执行后端重型测试；它不代替 Web／Android 构建后创建新 ID 的联合会话验收。公共环境未部署，联合真实验收仍待 Android，其余场景按各仓证据逐项确认，不能将 17 项矩阵整体标为已通过。

跨端验收使用该提交的统一隔离 runner，登记独立 PostgreSQL、Redis、私有对象存储夹具、API 与 Worker 身份；两端固定构建并开启会话后才创建新版本。Web 与 Android 顺序使用同一 runId、资源和账号，状态推进须等双方完成，不混入会修改状态的后端功能套件；消费者结束后由 runner 统一清理。后端功能测试的随机 ID 和 `synthetic-legacy-readiness-only` 记录不能冒充真实历史导入或跨端核心证据。执行入口及参数直接以生产者[同一 runId 的跨端会话](https://github.com/morenk/wenyousite-backend/blob/62a0313a75c85e42dfa39cd09b7cc90ae5c34186/docs/dynamic-text-fonts.md#同一-runid-的跨端会话)为准，本仓不启动写入验收或改变公共服务。

可信历史导入固定 `sourceManifestSha256` 并声明 `preserveAssetFamily=true`，逐对象核验源清单、SHA、长度及原 family。新构建使用 `WYF2-32hex-shard`；导入保留已验证的 `WYF1-16hex-shard`、原 SFNT／WOFF2 字节和 SHA，两种 family 均可出现在 v2 清单中。匹配名称形状本身不证明来源可信，不能给导入资源重取别名。

v1／v2 共用同一运行时注册账本，先读 v1 再读导入 v2 的相同 `(assetSHA,family)` 不新增原生尝试或重复收费。共享 `legacyImportRegistrationCases` 已原字节同步并核对源清单；Mobile 仍须在真实引擎执行，不能以静态预期或仅比较文件 SHA 代替零新增注册证据。不同 family 即使 SHA 相同也继续分别计费，目录更新与协议切换不得清账。

Foundation 机器体验契约、Token、生成产物、包版本及正式 Tag 不变；消费者保持各自已发布版本，业务协议直接固定 Backend 已提交契约；[发布与锁定核验](thread-font-admin.md#已发布产物与复现)区分 Web 的 v7.6.0 和 Mobile 已提交快照的 v7.5.0。契约切片检查通过后可以交接，运行功能未验收前不宣称整项完成或可发布。
