# 通知分组契约

通知事件的产生、传输、存储和 API 枚举继续由后端通知契约拥有。Foundation 只固定 Web 与 Flutter 共同呈现的筛选语义，客户端不得各自复制或改名。

| 分组 | 事件类型 | 用户意图 |
|------|----------|----------|
| 互动 | `reply`、`mention`、`follow`、`like` | 查看其他用户直接对我或我的内容产生的互动 |
| 订阅 | `new_post`、`thread_created` | 查看我关注的主题帖或用户发布的内容更新 |
| 系统 | `tip`、`level_up`、`system` | 查看温油、等级与站方产生的账户和系统消息 |

“全部”始终是默认入口，不计入三种业务分组。分组只影响列表筛选，不改变通知事件类型、单项图标、文案、跳转、未读状态或推送协议。

当前已知事件必须且只能属于一个分组。后端增加了客户端尚未认识的事件时，该事件仍应出现在“全部”中；Foundation 契约升级前不得由客户端擅自猜测归类。

两端保持“全部、互动、订阅、系统”的名称和顺序一致，具体控件密度、触控尺寸和横向布局分别遵循 Web 与 Flutter profile。
