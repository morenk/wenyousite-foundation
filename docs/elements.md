# 核心元素系统

本规范治理正文与元数据中的最小可复用视觉单元。机器事实源为 `contracts/foundation.v1.json` 的 `experiences.elements`；业务协议、页面布局、卡片和浮层仍由各自生产者或既有契约拥有。

## 共同边界

- 状态与类别不能只靠颜色表达；文字、图标、前缀或结构至少保留一种非色彩线索。
- 阅读态与编辑态使用等价元素。编辑器中的传送门保持原子编辑并阻止导航，发布后才按链接行为打开目标。
- 非交互 Badge 按内容收缩，不为视觉对齐伪造点击命中区；独立可点击元素服从 Web 32px、Flutter 48dp 的平台下限。
- Markdown、站内坐标与通知数量仍由后端/API 契约拥有；主题帖分类 API 不定义颜色字段。

## 正文内联与块级元素

| 元素 | 识别线索 | 核心呈现 |
| --- | --- | --- |
| 站内传送门 | `content.internal-reference` 门图标 | 柔粉轻量内联胶囊、可换行、不截断；hover/pressed 使用共享状态层 |
| 普通链接 | 下划线 | 品牌深色、600 字重；外链在新标签页打开 |
| 提及 | `@` 前缀 | 品牌深色、无底色；编辑态作为原子语义 |
| 行内代码 | 等宽字形 | 中性浅底、紧凑内边距，不生成块级卡片 |
| 骰子 | 总计或 `?` | 已结算使用品牌色对，待掷使用警告色对与问号；固定为与正文基线对齐的无图标原子节点 |
| 引用 | 2px 深莓书签线 | 中性浅底、起始侧直角、正常字形，不强制斜体 |
| 分隔线 | 居中短线与圆点 | 正文可用宽度 50% 的 1px `border` 短线叠加 `brandStrong` 圆点，区别于满宽内容边界 |

Flutter Quill 编辑态的行内代码是明确的平台渲染例外：字体、字号、颜色和圆角仍与阅读态一致，仅内边距使用 Quill 原生背景边界。该例外不适用于 Flutter 阅读态、Web 或其他内联元素，也不削弱 Markdown 往返语义。

### 引用渲染

- 引用是普通 Markdown 长引用，不承担回复预览、提示信息或编辑性拉引；回复来源、作者和跳转继续由业务组件拥有。
- 引用占满正文可用宽度，使用 `muted` 底色、`foreground` 正文色与 `brandStrong` 起始侧书签线。Web 侧线为 2px，Flutter 为 2dp；侧线所在两角保持直角，远端两角使用平台 `compact` 圆角。
- 正文继承阅读态 body 字体、字号与行高，保持 400 字重和正常字形。不得自动添加引号、图标、阴影、文楷或斜体；作者在内容中写入的引号原样保留。
- 内边距固定为纵向 `0.5em`、横向 `0.75em`。外间距沿用平台正文块节奏；首尾子块收口自身外间距，多段、列表等内部结构继续保留可读间隔。
- 阅读态与编辑态使用等价书签纸条。平台实现必须消费生成 Token 或常量，不得分别选择近似颜色、宽度与圆角。

### 分隔线渲染

- 分隔线表示作者在同一篇正文内安排的停顿，不承担卡片、楼层、列表项或区块边界语义。
- 阅读态与编辑态都使用居中的短线圆点：首选总宽为正文可用宽度的 50%，旧渲染器以 5em 兼容回退；线宽 Web 1px / Flutter 1dp、中央圆点直径 5px / 5dp，上下各留 1.75em。
- 短线使用 `border`，圆点使用 `brandStrong`；形状而非颜色是主要识别线索。不得拉伸到正文满宽，也不增加渐变、阴影、文字或动画。
- Markdown 仍使用原生 thematic break 语义；圆点只作视觉标记，不进入复制文本或辅助技术名称。

### 骰子渲染

- 可见主文案只显示规范化表达式和总计：已结算为 `{notation} = {total}`，待掷为 `{notation} = ?`。即使有多枚骰子或修正值，也不把逐骰数组塞进行内正文。
- 全部已结算节点都可打开逐骰明细，待掷节点不可操作。主文案不追加箭头、图标或“点击查看”；Web 通过 pointer、hover/pressed 和焦点环表达交互，Flutter 通过按钮语义与 hint 表达。
- 触发器的可访问名称只包含表达式和总计，避免一次朗读最多 100 个点数；打开明细后，逐枚结果按“第 N 枚，X 点”的顺序语义读取。Web 支持 Enter/Space 打开并在关闭后恢复焦点。
- 节点使用 utility 字体与等宽数字，和正文基线对齐，内部不换行、不截断、不显示骰子图标。内部行高固定为 1.5、垂直内边距固定为 0.04em；17px 正文下底色约高 27px，正文自身行高不变。
- 阅读态与编辑态使用相同文案和色对；编辑器中只作原子选择，不打开明细，也没有点击投掷、重新投掷或导航行为。
- 客户端只按 `nodeId` 绑定后端返回的不可变结果，不能按数组顺序关联，也不能本地生成或修改正式点数。找不到结果时保留待掷态，不伪造结果。

### 骰子明细与插入

- 明细使用“数字骰盘”：逐骰点数按服务端数组原始顺序放入自适应数字格，统一使用 `muted` 底色、正文色、utility 字体和等宽数字。Web 使用 22rem 锚定 Popover，最大高 28rem；移动端使用最高 80% 视口的安全区 Bottom Sheet，长骰池均在内部滚动。
- 计算区依次显示“骰面小计”“修正”“总计”。小计由服务端逐骰数组求和，修正只在非零时显示为 `+K` 或 `−K`，最终总计始终使用服务端值。
- 插入器将表达式拆为“骰子数”“面数”“修正”三个数字字段，默认 `1d20`、零修正。`d4/d6/d8/d10/d12/d20/d100` 只快捷替换面数，实时预览 canonical 待掷表达式；数值范围仍由后端正文协议拥有。

### 内联底色密度

- 传送门和骰子都使用 1.5 内部行高与 0.04em 垂直内边距，在不缩小文字、不改变段落行高的前提下收紧底色高度。
- 传送门继续使用 `accent/onAccent`、门图标和可换行语义；已结算骰子继续使用 `accent/onAccent`，待掷骰子继续使用 `warningSoft/warning`。本次不增加新色板或装饰图形。

## 元数据元素

- Badge 只有 `default` 与 `compact` 两种尺寸，tone 固定为 `neutral`、`brand`、`success`、`warning`、`danger`、`info`；所有 tone 复用既有色对。
- 主题标签是可点击浏览入口，只以 `#` 与 `brandStrong` 粉色文字提供常驻视觉线索，不使用底色、描边、圆角或胶囊包裹；悬停增加下划线，键盘焦点环保持可见。Web 命中高度不小于 32px，Flutter 不小于 48dp。标签不借用仅属于点赞状态的 `like` 专色。
- 等级固定为 `Lv.N`，使用紧凑圆角和 utility 数字。Lv.1 为雾灰，Lv.2–3 为杏桃，Lv.4–5 为玫瑰，Lv.6–7 为珊瑚，Lv.8–9 为深莓实心白字；色彩从低到高提高彩度与强调度，但文字始终是等级的非色彩线索。未来更高等级沿用最高档，无效等级不渲染。
- 等级经验进度的填充跟随当前等级档，轨道保持中性。普通进度、上传和等待不能借用等级色。
- 身份角色按职责分层：楼主和站务使用品牌 tone，协作者使用 info，玩家与普通成员保持 neutral。头像缺失或加载失败使用首个可读字符，匿名或失效身份使用中性用户图标。
- 邮箱是否验证不属于身份展示：列表、详情和个人资料不显示徽标或状态；账号安全入口与受限操作引导由认证业务保留。
- 置顶/新内容使用品牌 tone，私密/锁定使用 warning，归档/失效使用 neutral，封禁/错误使用 danger。收入可用 success，正常支出保持普通前景色。
- 未读数隐藏零值、超过 99 显示 `99+`。
- 分类不使用专属色。Web 线路保持 4px 结构宽度并统一使用 `mutedForeground`；分类 Badge 复用 neutral tone，且必须同时显示类别文字。
