# 主题帖正文字体

本文规定作者选择正文字体时的共享体验。应用 UI、未指定字体的正文与平台排版尺度继续消费 [Foundation 机器契约](../contracts/foundation.v1.json)；作者选择是正文内容属性，不新增 `body`、`display`、`utility` 角色，也不修改 Foundation 的空 `fonts` 清单。

## 范围与事实源

- 首批目标为用户 revision 4 确认的 17 个风格有明显差异、支持中文与英文的字体家族（原 11 款、仍保留的 3 款 BOOTH 字体及本次新增 3 款），不补足此前的 30 款目标；字重、斜体或资源分片不能重复计为不同家族。它们用于一般文字表达，不加入特效模板、动画、渐变或任意字体上传。
- 应用导航、控件、用户名、时间、计数、主题标题和列表摘要继续使用系统字体；不得把作者选择写入全局主题、整页字体或持久化为应用外观偏好。主题、子帖、楼层、回复等具体正文写入范围以 Backend 的能力与协议为准，不据共用编辑器扩大到动态或私信。
- Backend 唯一拥有字体目录、稳定 `fontId`、家族及中英覆盖、授权与来源、字重资源、Web／Mobile 文件及分片、版本／摘要、分发与能力声明，以及字体和颜色组合的 Markdown、剪贴板、摘要、错误与旧端覆盖保护。本仓不另建运行时目录或分发字体文件，不另定 HTTP API、属性语法和资源版本；测试所需目录只保留带来源哈希的原字节镜像。
- 正式接入固定 Backend 提交 `1cf51dd752a98e3733f3dc0c83b17add75be7e46`（OpenAPI `5.41.0-dev.20261021.1`）。[字体协议 v1](https://github.com/morenk/wenyousite-backend/blob/1cf51dd752a98e3733f3dc0c83b17add75be7e46/docs/markdown-text-font-v1.md)、[资源规则](https://github.com/morenk/wenyousite-backend/blob/1cf51dd752a98e3733f3dc0c83b17add75be7e46/docs/thread-font-assets.md)、[家族目录](https://github.com/morenk/wenyousite-backend/blob/1cf51dd752a98e3733f3dc0c83b17add75be7e46/contracts/thread-font-catalog-v1.json)与[资源 manifest](https://github.com/morenk/wenyousite-backend/blob/1cf51dd752a98e3733f3dc0c83b17add75be7e46/contracts/thread-font-manifest-v1.json)是本次来源；消费者直接同步该生产者契约，不依赖未发布的 Foundation 运行时产物。

该提交登记 17 款，其中 16 款资源为 `ready`，小城拉风体为 `pendingSource`。三款 BOOTH 原始 ZIP 已完成来源及许可核验，资源构建与字符覆盖以该版本 manifest 为准；`ready` 只表示本地资源已核验，不代表已经发布、覆盖全部中英字符或通过消费者验收。小城拉风体继续按负责人本轮确认的项目使用授权推进，待原件及完整性核验，不重新要求项目授权。

## 协议接入与共享验证

字体使用独立 v1 协议，与颜色共用受控 `span`；字体属性在前、颜色在后，接受逆序输入并规范化。字体与颜色之外不扩展 HTML／CSS 白名单，不允许嵌套、空区间或跨物理行 span；粗斜删、普通链接与行内代码在内，块前缀在外，跨原子选区拆开。去掉最后一个属性时按完整内联语义重序列化，不能简单删标签而激活字面 Markdown 或破坏相邻 marks。精确语法和规范输出以源协议与语料为准。

读取分别声明 `X-Text-Font-Version: 1` 和颜色读取能力；支持新协议的客户端在所有正文写入 DTO 始终声明 `textFontVersion: 1`，包括删除全部字体的保存，不能以请求头代替 DTO。组合颜色需同时声明 `textColorVersion: 1`；正文创建、编辑、BODY upsert、聚合保存和云草稿各入口都需覆盖。字体与颜色四种读取组合如下：

| 字体能力 | 颜色能力 | 组合内容的读取结果 |
| --- | --- | --- |
| 有 | 有 | 保留字体与颜色 |
| 有 | 无 | 只保留字体 |
| 无 | 有 | 只保留颜色 |
| 无 | 无 | 安全 Markdown 原文与其余 marks |

新写默认关闭；后端能力缺失按 false，不显示可创建字体的入口。关闭新写时可保留、重排或移除已有范围、编辑无字体文本；不能新增、改字体或改已有字体范围内的文字与 marks。颜色变化单独受颜色门控。缺 DTO 能力、禁用新写及非法字体分别由 Backend 的 `TEXT_FONT_CAPABILITY_REQUIRED`、`TEXT_FONT_DISABLED`、`INVALID_TEXT_FONT` 拒绝；客户端保留输入并就地反馈，不能静默降级重试覆盖。完成所有保存入口和保源路径后再声明能力。

`GET /meta/text-fonts` 返回目录、状态、manifest 描述符和 `assetBaseUrl`。base 为 `null` 时不请求字体、manifest 或上游来源；只有自有发布地址、相应能力和可用状态满足时才加载。新写还须满足独立新写开关，不能把 `ready` 或资源可下载当成允许写入。缓存按后端 `Vary` 保留字体／颜色／角色提及能力区分，不能把去样式副本覆盖原始内容。

[字体 Schema](../tests/fixtures/text-font/markdown-text-font-v1.schema.json)、[四种投影及写入语料](../tests/fixtures/text-font/markdown-text-font-v1-fixtures.json)和[目录镜像](../tests/fixtures/text-font/thread-font-catalog-v1.json)按源提交原字节保存在测试目录；[来源记录](../tests/fixtures/text-font/source.json)固定 SHA、路径、长度和哈希，并记录大型 manifest 及生成索引的来源校验信息。镜像只用于验证，不随 Foundation 运行时包分发，不是另一套可编辑目录；更新时从明确 Backend 提交整体同步。`pnpm test:text-font` 验证镜像完整性、目录身份与 Schema 同源、有效／无效解析结果及语料完整性，不代替消费者执行 Markdown 投影、HTTP、编辑器、加载和设备验收。

## 内容与编辑

- 同一 `fontId` 在 Web 和 Flutter 指向同一家族；原文、中英文、标点、空格、换行和 emoji 保留。两端不以本机字体名、展示名、数组位置或下载 URL 代替持久化身份，也不因平台资源不同存成另一个字体。
- 字体与文字颜色、粗体、斜体、删除线等属性分别修改；换字体或恢复“默认”只改变字体属性，不能清除颜色和其他格式。字体、颜色与普通链接、行内代码、标题、列表、引用的合法组合、优先级和序列化均以 Backend 固定语料为准，不由 CSS 继承或第三方解析器偶然决定。原子节点保持自己的身份与呈现。
- 有效文字选区只修改适用文本；跨段按协议支持的行内范围处理，混合字体不误报为某个单一家族。打开选择器、滚动或预览不改原文；应用一次形成一次可撤销格式事务，取消恢复原选择与焦点。无效选区和仅含不可格式化节点的选区不产生空标记。
- 有效折叠光标允许先选字体后输入；选择本身不改文档、草稿或撤销栈。连续输入、中文输入法组合与换行保持显式输入字体，主动移动光标或重开文档后按新位置恢复；默认只清除输入字体，保留颜色等状态。富文本粘贴按来源保留合法格式，不用当前输入字体覆盖粘贴内容或原子节点；未输入的临时状态不写入草稿。
- 编辑态、选择器样字预览与阅读态使用相同的家族解析、可用字重和缺字回退。首批每家族只有一个默认字款，OFL 派生 face 的基础字重／样式以 manifest 为准；粗斜体仍是独立 marks，两端使用一致合成策略并实测效果，不把不同字重计为新家族。使用现有字号、行高、段落层级和系统文字缩放；不能为了某个家族缩小字号、强制字宽或裁掉高字形。平台字形栅格化和换行允许差异，不承诺像素相同。
- 草稿、重开、站内富文本剪贴板和跨端编辑往返保留合法字体及颜色组合；纯文本复制、摘要和读屏保持可读原文，不泄漏协议标记。资源未到达不能成为丢弃字体属性的理由；解析或转换无法保源时阻止覆盖保存，保留编辑现场并给出可恢复的错误。

## 选择器与加载

- 复用现有正文样式入口和平台控件，不新增常驻主工具栏按钮；显示字体名称、默认、选中态及必要加载／失败状态。名称始终使用 UI 系统字体，样字提供中英混排；不为每个家族添加说明段落、营销文案或装饰卡片。
- 预览使用 Backend 提供的轻量资源或当前单项按需样字；不可为了展示首批 17 个家族的目录先下载全部完整正文字体。未有真实样字时保留名称与加载状态，不能把系统回退伪装成该家族的实际效果。
- 最近使用只记录已确认使用的 `fontId`，按账号保存在本机、去重并保持有限条目；悬停、滚动和失败预览不计入，不跨账号泄漏。最近使用列表本身不触发字体下载或后台预热，条目失效不改历史正文。
- 正文只为当前需要展示或编辑的文本加载相应家族和资源；新进入视口的内容再按需处理。请求去重、有界并发，可复用已校验缓存；快速切换、关闭面板与离开页面时停止无用工作，迟到响应不得覆盖新选择。不在启动、登录、打开选择器时批量下载所有家族。
- 未知字体、字体未到达、断网、下载失败、哈希不匹配、缓存被回收、缺字或超过预算时立即以系统回退显示原文，保留请求的 `fontId`。缺少某个字符时按字符回退，不能用空白、方框占位或替换文字冒充支持；验收中文生僻字、中英标点和 emoji。下载失败不阻断阅读和保源编辑，重试有明确触发且不循环耗流量。
- 字体到达会改变字宽和换行，须保持当前可见文字锚点及其视口位置、光标、选区和输入法状态，并更新长列表测量；不能跳回顶部、跳到另一楼层或反复闪烁。不可安全替换时延后该次显示切换并保持可读回退，不以锁死高度、截断或隐藏正文维持假稳定。

## 平台资源与成本

Web 与 Mobile 使用同一业务身份，但消费各自的资源描述，不要求相同文件或加载机制。具体差异见 [Web profile](platforms/web.md#主题帖正文字体) 和 [Flutter profile](platforms/mobile.md#主题帖正文字体)。消费者遵守该版本 manifest 的 `limits`，运营分发预算与客户端预算分开执行，本仓不另建数值表；交付需报告配置与实测，不能仅写“按需”或“有缓存”。

小城拉风体的本项目使用授权依据为负责人本轮明确确认，按该确认推进接入，不再仅因网页一般条款挂起，也不重复要求授权。此依据不改写为 OFL，不虚构授权文书或自动扩展为修改、转换、拆分许可；本轮保留原文件接入方案，不进入子集、分片或 WOFF2 转换流水线，完整字体成本以已提交 Backend 资源记录和后续原件核验为准。其他字体也须按各自已核验许可选择完整文件或派生资源，不因同属目录而共用一套转换假设。

资源加载先验证 manifest 描述符，首次使用家族时同时取得并校验完整许可与归属，随离线缓存保留；字体通过实际长度和完整 SHA-256 校验后才缓存或注册。只复用已验证缓存，损坏缓存最多重试一次，失败进入本次会话回退；预览、许可和归属请求也计入预算。派生资源展示名直接使用目录的 `name`，不以来源名称覆盖它；原始字体名用于归属，避免将 RFN 当作派生主名称。

| 成本 | 共同要求与验收证据 |
| --- | --- |
| 安装包／首屏 | 不将首批 17 家族完整资源捆入安装包或首屏；报告包体增量、首屏和仅打开选择器时的请求及字节数。 |
| 网络流量 | 区分轻量样字、正文所需资源及平台分片；记录冷缓存、重复阅读、快速切换、失败重试的请求和实际传输量，证明没有无关家族批量下载。 |
| 磁盘缓存 | 依据后端资源版本与校验身份复用；记录实际缓存上限、淘汰和损坏恢复。清理文件不删除文档字体属性，空间不足仍可读。 |
| 运行内存 | 区分下载／解码缓冲、已注册字体与页面对象；记录多家族长文、连续预览和离开后的峰值及保留量，设置有界工作量。若平台不能立即卸载注册字体，明确其生命周期和累积限制，不以磁盘淘汰冒称释放内存。 |

## 验收与交付

- 目录验收依据 Backend 已提交版本，确认首批 17 个家族的数量口径、完整资源可用状态、许可、真实中英文样字与风格差异；Foundation 文档不代表该目录、授权或字体质量已通过验收。
- Web／Flutter 使用同一后端语料验证选择局部文字、跨段、混合字体、先选后输入、中文输入法、颜色与格式组合、默认、取消、撤销／重做、草稿、复制粘贴及 Web → App → Web 往返。资源失败不改原文与属性，无法保源不发覆盖写请求。
- 覆盖冷缓存、离线、缺字、资源失效／损坏、快速切换、目录更新、缓存回收，以及字体异步到达时的长讨论阅读锚点和编辑选区；按上表分别提供流量、包体、磁盘和内存证据。预算按首批 17 款目标调整，逐项区分已核验资源实测与缺资源的未测项，不以旧 30 款预算或预览大小替代；此前 audit-v3 的 11 款子集实验不再作为正式构建成本依据；当前 16 款构建产物的分片、覆盖与实际字节数直接引用上述 Backend manifest 和资源规则，也不能冒称完整 17 款或运行内存实测；预算数值与未覆盖项随消费者交付，不在本文猜测。
- Web 提供桌面／窄屏、明暗、缩放和键盘操作画面；Mobile 在 Windows 提供窄屏、明暗、大字号、安全区与键盘状态画面。负责人确认实际样字、可读性、选择效率与滚动体验；文档检查不代替视觉或真机验收。真实环境自动化只读，写入 E2E 仍使用本轮核验的独立隔离资源。
- 此次补充业务接入文档、规则和测试镜像，不新增 Foundation Token、Schema、导出、生成常量或版本；无需新 Tag，消费者继续锁定已发布版本，可保持 `v7.6.0`。若实际实现必须新增 Foundation 运行时规则，则报告发布依赖，等待负责人明确版本与正式发布，不能引用未发布提交或复制候选常量。
- 新写开放、旧端降级和关闭新写时的保源依 Backend 协议执行，顺序为兼容后端 → 可读保源消费者 → 开放新写。合并、Tag／Release 和部署仍须明确授权；本次不删除旧协议或字体迁移历史，回滚也不能静默抹掉已保存字体。
