# 字体后台上传与列表管理

本文为本轮管理员流程简化的行为准备，等待 Backend 已提交契约后补齐精确来源与共享语料。当前不定义 HTTP 路径、DTO、错误码、幂等键、游标格式、修订字段或默认样张文本，不可据此宣称新接口可用。

本文与[动态正文字体规范](thread-fonts-dynamic.md)及既有镜像共同在字体 PR #38 交付。旧规范固定的 Backend 契约仍是已接入依据；本页三字段流程是待新提交确认的目标，不提前覆盖旧接口约束或将 PR 视为已合入 main。消费者字体 v2 协议不变，旧正文身份、授权材料、不可变资源与审计保留。

## 提交与授权确认

管理员的上传输入收敛为文件、名称、语言。语言默认 `other`，样张使用 Backend 契约确定的默认值；界面不要求管理员为提交补填样张、来源、作者、许可正文或排序。默认值必须由同一生产者契约确定，不能两端各造一份。

上传即确认所需授权，并形成可追溯审计；用靠近提交操作的简短必要提示说明此后果，不增加重复确认、许可表单或常驻解释段落。审计的身份、确认时点、范围及幂等关联等待 Backend 定义，不用客户端勾选状态替代服务端记录。已有授权和来源记录不因简化表单而删除或覆盖。

缺少许可元数据本身不阻止受支持文件继续处理；检测到明确的禁止嵌入、转码、分片或其他契约列明的限制时仍须拒绝，不能把“未提取到信息”等同于“明确受限”，也不能把上传确认解释为绕过技术限制。拒绝保留管理员可恢复的输入并给出简短原因，失败不进入可发布状态。确切限制分类、错误和审计以已提交 Backend 契约为准。

## 阶段与失败恢复

一次管理员意图应能关联上传、处理和发布各阶段；超时或结果未确认时，先恢复该意图的已知阶段，不盲目重建家族、重传原件或重复发起已完成操作。双击、重试、刷新后恢复和重复请求不能制造重复任务、版本、发布或授权确认记录；各阶段的幂等范围与可重试条件由 Backend 机器契约定义。

界面状态依据服务端结果呈现，处理中不冒称已发布，失败不清空仍需恢复的文件信息、名称与语言。已完成阶段的合法产物可按契约复用，原始字节及历史版本不可覆盖。是否提供阶段按钮、何时自动续行以及页面刷新后的恢复载体，收到契约后再定，不提前绑定旧的多表单流程。

## 后台列表与公开顺序

后台查看顺序只影响管理员检索，不改公开目录的 `sortOrder`。全量筛选必须由服务端应用到完整结果集后分页，不能只过滤已加载页；筛选或查看排序变化后按契约重启分页。稳定顺序、并列项处理、游标与并发变更语义以 Backend 为准，不用前端数组位置补造业务顺序。

公开目录展示重排是独立写操作，只允许同语言范围内移动。提交基于已知修订，冲突保留当前视图和待执行意图，刷新后重新确认有效位置；不能强行覆盖其他管理员的变化。跨语言移动、无效目标、重复提交和顺序已变化的处理由生产者契约明确。目录重排不创建新字体版本、不迁移旧帖身份，也不改变停用／撤回状态。

列表保持[Web 管理后台](platforms/web.md#管理后台)的信息密度、键盘操作、焦点和窄窗口可达性。字段与按钮能表达的含义不再用副标题或常驻提示重复；恢复错误和授权后果仅在需要的位置呈现。查看筛选、公开顺序修改及处理状态不得合并成一个含糊的“排序／保存”动作。

## 兼容与验收准备

下列用例是行为审查清单，尚无生产者新接口夹具或执行结果。收到 Backend SHA 后逐项关联原字节语料和真实实现测试；不编写只匹配文案的测试或模拟成功的流程执行器。

| 用例 ID | 必须观察的结果 |
| --- | --- |
| `admin-three-fields` | 只用文件、名称、语言完成受支持的提交路径；默认语言 other，样张与 Backend 默认一致，无额外必填许可表单。 |
| `admin-upload-consent` | 上传确认关联管理员、意图及资源，审计可查；重试不重复记确认，已有授权材料完整保留。 |
| `admin-license-metadata` | 无许可元数据不阻塞；明确受限文件被拒绝且不发布，拒绝原因不泄漏处理器或内部路径。 |
| `admin-stage-resume` | 上传／处理／发布分别遇到失败、响应丢失、重复提交及刷新后可恢复；完成阶段不重复执行，不产生重复版本或发布。 |
| `admin-global-filter` | 目标在未加载页时仍能筛选得到；筛选、查看排序及分页边界稳定，不能混合旧查询结果。 |
| `admin-view-order` | 更改后台查看顺序不写公开 sortOrder，不产生公开目录重排或新的内容版本。 |
| `admin-language-move` | 同语言移动正确更新目录展示顺序及修订；跨语言／无效目标拒绝，冲突不覆盖他人结果，重复请求按契约处理。 |
| `admin-history-preserved` | 新流程保留历史许可、来源、资源、固定引用及审计；消费者 v2、旧 v1 映射、停用／撤回和防有损覆盖保持兼容。 |

Web 提供实际明暗和窄窗口预览，以及授权提示、错误恢复、筛选与重排状态的可见证据。写入 E2E 只使用本轮登记的独立数据库、Redis、存储和账号，记录 runId、前后端提交、资源身份及退出清理；测试失败或清理失败都不能记为通过。Foundation 只同步共享依据，不以文档检查替代后台画面、后端审计或隔离写入验收。

## 接入与交付边界

Backend 新 SHA 到达后，先比较管理员 OpenAPI、默认值／样张、授权确认审计、阶段幂等与恢复语料、全量筛选分页和同语言移动修订语义；保留已提交原字节及来源摘要，可追溯投影明确标注源指针。旧接口是否保留或弃用由生产者契约决定，不凭表单精简删除历史字段或数据。

新契约到达后在同一字体分支更新管理员规范、来源镜像、兼容登记和测试入口；既有消费者镜像与待验收项继续保留，整套变更通过 PR #38 交付。未收到新契约前不猜接口，不迁移消费者协议。Foundation 包版本、机器体验契约、Token 与生成物不变，不创建 Tag、Release 或部署。
