# 温油站共享设计基础

## 产品与气质

温油站是多人文字共同创作社区。视觉关键词是温暖、轻快、社区感、圆润、信息清楚；核心任务是发现、阅读、创作和管理内容，不是展示品牌装饰。

正式品牌名称、文案、标识语义与平台资源由 [`brand.md`](./brand.md) 和 `experiences.brand` 统一。标识用于启动、认证身份与紧凑标题识别，不扩散为页面装饰。

- 页面使用可切换的阅读画布：亮色保持白纸感，黑夜使用温暖墨紫背景与稍亮的纸面表层。柔粉主要表示品牌和局部反馈；鲜粉点赞、金色收藏与品牌色订阅只在用户已建立对应互动关系时出现，选中图标不使用常驻背景。
- 圆润不等于幼态：避免糖果渐变、纯黑大底、霓虹高光、玻璃拟态、粗阴影和无意义插画。
- 信息结构本身构成视觉。作者、时间、状态、关系和操作不能为了“简洁”被隐藏。
- 唯一高辨识度元素是带真实分类语义的线路标记；不创建虚假编号、时间线或第二套品牌概念。
- 亮色与黑夜必须保留相同的信息层级和交互语义；状态、焦点和交互不能只靠颜色表达。

## 颜色、字体与动效

共享色板以 `contracts/foundation.v1.json` 为准。亮色使用白色画布、深紫灰正文和克制柔粉；黑夜使用温暖墨紫画布、暖灰紫正文、可辨认的深浅表面以及更明亮的品牌强调色，不把亮色色值机械反转。主操作消费 `actionPrimary` 色对，柔和选中与容器状态消费 `primary` 色对，结构标记消费 `brandStrong`；点赞与收藏继续使用各自关系色。普通文字、控件边界和焦点在两种模式中都满足对应的 WCAG AA 或非文字对比要求。核心导航、操作、编辑器能力和常见状态使用同一份语义图标契约，具体映射、互动状态与贡献规则见 `docs/icons.md`。

## 主题与表面

- 用户偏好有“跟随系统、亮色、黑夜”三种，默认跟随系统；解析后的模式只有亮色与黑夜。客户端在本机持久化显式偏好，系统偏好只在“跟随系统”时实时生效。
- 主题切换只改变语义 Token，不改变布局、内容顺序、资产裁切、图标含义或信息密度。正文图片、封面、头像与用户上传内容不做反色、降亮或着色滤镜。
- 页面画布、内容表面、柔和状态层和浮层按语义逐级分离；不能用透明玻璃、环境渐变或大面积发光代替层级。黑夜阴影与遮罩使用专属 Token，避免沿用亮色灰影。
- 品牌标识保持既有几何与可访问名称；客户端在黑夜表面使用可读的品牌色版本，不新造第二套标识。
- 浏览器控件、表单原生外观、选区、焦点、编辑器和第三方浮层必须跟随解析后的主题；不能留下局部亮白“孤岛”。

排版保留三个稳定语义角色：`body` 用于正文、控件与长时间阅读；`display` 用于品牌、内容页面/区块结构标题、详情内容主标题和文字封面；`utility` 用于数字、时间、计数与短标签。三个角色均声明 `system-ui`，fallback 为 `sans-serif`。字号、行高、支持字重及使用场景以 `typography` 和平台 `typeScale` 为准，通过层级和字重区分内容，不绑定具体字形。列表项主标题使用 body 600，并继承当前主题正文色；Dialog、Sheet、Popover 与空/错/加载状态标题、用户名、导航、控件和富文本内部标题继续归入 body。

设置与管理界面的页面、区块和子区块标题属于 functional 标题语境，统一使用 body 600，保留对应平台的标题字号与行高；管理中显示的帖子名称也属于功能标题，不套用正式阅读标题的 display 规则。此规则覆盖资料与账号设置、帖子管理/编辑、发布设置、导出设置及站务台（含站务登录、邀请接受和操作弹窗）；不扩展到普通认证、创建与草稿续写、消息通知、钱包收藏、用户举报申诉或内容浏览页面。数字、时间和计数继续使用 utility 字体。

Foundation 的 `fonts` 为空，不捆绑或运行时下载字体。Web 使用系统字体栈；Flutter 继承平台默认字体与系统缺字回退，不把 CSS 家族名注册为 Flutter 字体。不同系统的中文、数字和中英混排行宽允许不同；消费者仍须验证换行、溢出、系统文字缩放及可读性。数学排版字体、系统等宽字体与平台图标字体不属于本次迁移范围。

常规反馈使用 120–240ms 的颜色、边框、透明度和短位移；动效只解释状态反馈、展开收起和浮层关系。尊重减少动态效果，不使用持续漂浮、环境循环、列表布局跳动或视差。

## 文案与状态

- 使用用户认识的功能名称和主动语态；按钮、完成提示和错误保持同一动词。
- 错误说明发生了什么以及下一步；空状态只提供真实可执行动作。
- 内部 Token 名、设计概念、发布阶段和宣传式氛围文案不进入界面。

资源加载、刷新、分页、空结果、失败与受限状态，以及 Mutation pending、成功和失败语义由 [`interaction.md`](./interaction.md) 统一。界面导航名称、稳定产品名词和动作词见 [`navigation-language.md`](./navigation-language.md)。

正文中的传送门、链接、提及、行内代码、骰子、引用和分隔线，以及状态徽标、主题标签、等级、未读数和分类标记由 [`elements.md`](./elements.md) 统一。元素系统负责小尺度的形状、色彩、文字线索与跨端等价性；页面布局和业务协议仍分别由平台 profile 与生产者契约拥有。

## 主贴管理设置

发布后的“主贴发言权限”放在既有招募状态、可见范围所在区域，紧随可见范围，复用相邻字段的标签、说明、间距、控件和层级。Web 与 Flutter 分别保持自身设置页的信息密度和操作方式；不为权限增加独立卡片、专用弹窗或额外保存按钮。通用选项面板可以继续复用，不能将该字段拆成另一套管理流程。

说明文字为“仅影响主贴下的发言，子贴权限单独设置。”选项复用客户端现有子贴权限用语和三种策略：开放发言、仅楼主和协作者、仅玩家（楼主和协作者也可发言）。楼主和协作者从默认子贴的实际策略回填；不因加载中或失败而伪造开放状态。可见范围控制访问，发言权限控制主贴下的楼层与回复，其他子贴保留各自策略。创建流程与创建默认策略保持原状。

字段纳入各端现有保存机制、修改检测、离开处理和原上下文反馈：Web 使用当前表单统一保存，Flutter 使用既有自动保存、通用选项 Sheet 和离开等待。失败或版本冲突保留用户修改，pending 防止重复提交；保存成功后更新详情和发言能力。视觉验收覆盖完整设置页及相邻字段，不能只验证新增控件。

权限、事务和版本语义由 [Backend API 契约](https://github.com/morenk/wenyousite-backend/blob/223bc19137e3c6cee3911f9ca3b5f0bc63715d77/docs/api-contract.md) 拥有（`5.21.0-dev.20260911.1`）：聚合保存的可选 `defaultSubthreadPostingPolicy` 省略时保持原值，与其他主贴修改原子保存。Foundation 只说明共享体验，不重新定义 API 枚举或服务端授权规则；本次不增加设计 Token、不提升契约版本，客户端继续消费已锁定的 Foundation 发布版本。

## 集合与列表

结果、通知、收藏、会话、交易等集合的容器和列表项必须占满当前分配列；短标题、空摘要或窄内容不能让卡片收缩到内容宽度。多列展示必须由明确的网格或瀑布流规则决定，不能由每项内容长度偶然形成。

消息气泡、标签、徽标和紧凑操作可以按内容收缩，因为宽度本身承载对话方向、分类或操作语义。横向溢出只能用于已明确设计为可滚动的分类栏等场景，不作为列表宽度兜底。

列表负责扫描和进入：主标题使用 body 600，摘要只作可选预览。详情负责连续阅读：主标题使用 display 500，正文不拆成层层卡片，附属信息才进入面板。标题、身份、时间、摘要、封面、标签、指标、状态和操作使用统一语义槽位；帖子与动态只声明必要差异。完整规则见 [`presentation.md`](./presentation.md)。

通知中心固定使用“互动、订阅、系统”三组筛选，事件成员、未知类型降级和跨端边界见 [`notifications.md`](./notifications.md)。

## 图片

图片按头像、封面、正文、画廊缩略图和收藏表情区分角色。正文与表情必须完整呈现，头像和明确标注为封面的视图才允许裁切；已知尺寸时必须预留比例，失败、处理中、受限和敏感状态不能坍塌为无说明空白。具体契约见 [`images.md`](./images.md)。

## 编辑器

编辑器体验契约只规定跨端可观察体验，不复制 Markdown 语法。[后端 Markdown v5 契约](https://github.com/morenk/wenyousite-backend/blob/a91cbb8b605223c596af299be22c5547f69e25b9/docs/modules/markdown-content.md)继续拥有存储、规范化、扩展节点和剪贴板身份规则；只有工具栏主栏、“更多”面板及上下文入口提供的能力可成为结构化正文。客户端把白名单外 Markdown 静默显示为字面普通文字，API 直接拒绝未转义结构，未知协议不得交给第三方解析器决定产品能力。

编辑态和发布态共享正文大小、行高与块级层次。工具栏可以因平台和容器宽度改变入口位置，但同一能力的名称、可创建性、编辑方式、渲染结果和往返保障必须由中央能力生命周期说明。Web 额外固定正文首列与工具栏首项基线；Flutter 保留系统文字缩放、48dp 触控与原生底部面板。

段落对齐使用单一工具入口切换左、中、右三态，作用于普通段落与 H2/H3。内联提及、骰子和表情随父段落排版；列表、引用和分隔线保持各自既有布局，不继承也不创建对齐属性。独立图片按后端 Markdown v5 已有图片协议保留逐块对齐，不能因段落工具栏的适用范围而丢失阅读或编辑往返语义。

合法顶层对齐块不以作者在前文补空行为前提。阅读、编辑回填、草稿恢复、实际输入及保存重开必须保持相同的目标块与对齐；相邻普通正文、标题、图片或连续对齐块不能吞掉隐藏标记，也不能把某个块的对齐传给其他块。合法标记与目标仍须紧邻，目标范围与非法结构处理以 Backend 契约为准；代码、转义字面文本及原始 HTML 中形似标记的内容不能激活对齐。

合法普通正文的阅读与编辑保留作者实际输入的连续空格、行首空格、行尾空格和可见行，不能只保护格式节点之间的空格而折叠普通正文内部空格。按空格编排的文字仍是正文，不据此推断竖排、表格或等宽字体；不同字体、文字缩放与容器宽度下不承诺逐像素相同。WJ、NBSP 与全角空格不做全局替换；真正行末两个 ASCII 空格仍按既有显式硬换行规则拒绝。摘要继续采用既有紧凑纯文本语义。

解析所需的内部块分隔不能增加或吞掉用户可见空白行。主帖、子帖、楼层、回复和共用正文入口遵循同一语义；纯文本摘要与阅读复制不泄漏合法隐藏协议，站内粘贴保留既定正文语义和身份规则，多轮编辑保存不增殖标记。非法结构和未知协议仍按既有拒绝或字面降级规则处理，不扩大 HTML 或 URL 白名单。

跨端验收复用 Backend 已提交的[块边界组合用例 v1 revision 2](https://github.com/morenk/wenyousite-backend/blob/a91cbb8b605223c596af299be22c5547f69e25b9/contracts/markdown-block-boundary-v1-fixtures.json)及其中的 `whitespaceCases`，同时比较可见文字、块类型、逐块对齐、可见空白行和原始错误位置，并执行真实编辑事务、复制粘贴及多轮保存重开。当前编辑内容转换或校验失败时必须阻止提交旧正文，不显示保存成功，保留可编辑现场并明确提示错误；真实页面测试须断言失败时没有写请求，修正内容后可以保存。本文只补充可观察行为，不变更 Foundation 数值、机器契约版本或客户端固定版本消费方式。

## 变更规则

共享语义变化必须同时审视 Web 与 Flutter profile；平台特有变化只修改对应 profile，并在 CHANGELOG 标明 `shared`、`web` 或 `mobile`。客户端通过固定版本升级，不允许直接读取本仓库主分支。
