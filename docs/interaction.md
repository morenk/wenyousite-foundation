# 反馈、无障碍与浮层契约

## 边界

本契约规定 Web 与 Flutter 对异步状态、短暂反馈、模态交互和可访问性的共同语义，不定义后端错误码、请求重试策略或具体组件实现。机器事实源为顶层 `accessibility`、`experiences.feedback` 与 `experiences.overlays`。

## 资源与操作状态

- 首次加载只占据当前资源区域；刷新和加载更多保留已有内容，不能用整页转圈替换可继续阅读的信息。
- 列表与详情首次加载使用保持最终结构的 Skeleton；小范围未知等待与提交按钮使用 Spinner。减少动态效果时 Skeleton 保持静态，不脉冲。
- 空内容与无搜索结果是不同状态。空状态只有在动作真实可执行时才展示行动入口。
- 阻塞当前任务的错误留在页面、区块或表单上下文，并说明下一步；只有确认可安全重复的操作才提供重试。
- Mutation pending 必须阻止同一触发器重复提交。成功或失败后，同一个动作从按钮到反馈保持同一动词。
- Toggle pending 保持提交前的 tone 并显示同色加载指示，不能先闪回未选中态；点赞、收藏、主题帖订阅和普通 Toggle 的色彩与填充规则由图标控件契约拥有。
- Web toast 与 Flutter snackbar 只承载短暂确认。权限变化、保存失败、内容状态等关键结果必须同时在原上下文可见。
- 主题切换是即时界面偏好，不显示成功 toast 或 snackbar；切换控件自身的选中状态就是确认。主题变化不得引入装饰性全屏过渡，减少动态效果下必须同样完整可用。

## 无障碍

- 普通文字、大文字和非文字界面分别满足契约中的最低对比度；状态不能只靠颜色表达。
- 二态按钮同时使用填充/描边变化和平台状态语义：Web 提供稳定名称与 `aria-pressed`，Flutter 提供稳定名称与 toggled 语义；无法改变图形的普通 Toggle 必须补充可见状态文字，不能只改变颜色。
- 键盘焦点始终可见；独立图标控件提供语义名称，装饰图标退出读屏顺序。
- 异步进度默认礼貌播报，只有确实紧急的信息才打断当前朗读。
- Web 尊重浏览器缩放、系统颜色偏好与减少动态效果；Flutter 保留系统颜色偏好、文字缩放、安全区和系统返回。解析后的主题需要同步到浏览器或系统原生控件，不能仅改变应用内容区域。

## 浮层

- Sticky、应用框架、悬浮操作、菜单、模态、Tooltip、模态内二级浮层和全局进度使用中央语义层级，不在业务代码中竞争任意数值。
- 模态阻断背景交互，提供可见关闭入口，退出后恢复触发位置；遮罩点击不能成为唯一退出方式。
- Web 阴影、遮罩与层级由生成 CSS Token 提供。Flutter 使用 flat、floating、popup 三种 elevation 角色；平台原生动画可以不同。
- 图片查看器的高遮蔽背景和手势仍由图片契约拥有，不被普通模态规则覆盖。
- Tooltip 只提供短暂、非必要帮助；Popover 承载锚定的快捷操作、选择或上下文明细；移动端长选项、多操作和上下文明细使用 Sheet；阻断式决定、表单和确认使用 Dialog。
- 可撤销低风险操作直接执行并提供撤销；不可逆或影响他人的操作必须确认。确认标题和按钮明确说出动作，pending 时阻止重复提交和意外关闭。

## 本人关注与粉丝管理

本节应用既有控件、列表和浮层语义，不新增 Token、机器契约字段或组件 API。颜色、字号、间距、圆角、控件尺寸和状态反馈继续由当前已发布 Foundation 契约及消费者已有组件提供；接口、权限和关系数据以 Backend 已提交契约为准。

### 入口与列表

- 本人列表提供“关注／粉丝”同级页签，从个人主页计数进入时选中对应页签；保留既有地址、深链与返回行为。切换分别保留列表内容和滚动位置，重新进入时沿用平台已有恢复规则。
- 身份以头像和用户名为主，等级和关系状态为次要信息。复用现有扁平行或轻列表，避免为每个操作新增卡片、阴影或装饰色。
- 头像与用户名进入用户主页，操作区独立响应，点击按钮不触发行导航。“互相关注”是独立状态文字，不是按钮，不只通过颜色表达。
- 管理能力只在当前登录用户自己的列表出现，通过公开个人主页路径进入本人列表也适用；浏览他人列表保持已有行为。

### 同级动作与关系方向

- “回关”“取消关注”“移除粉丝”统一使用现有 secondary 角色的中性描边按钮：同一列表内使用相同 variant、尺寸档、圆角、文字样式和状态反馈。不得混入实心品牌按钮、无边框文字按钮，或为某个动作硬编码近似色值与尺寸。
- “移除粉丝”入口与另外两个动作保持同级中性外观；危险强调只在确认 Dialog 的提交动作中按既有 destructive 规范呈现。
- Web 在容器足够宽时将操作区放在行末，保持桌面信息密度与可见键盘焦点；窄容器不能挤压身份内容或造成横向溢出。Mobile 将操作区放在第二行靠右，保留单列、安全区、文字缩放，以及既有至少 48×48dp 命中区。长名称和大字体下允许内容增高、操作区自然换行，不缩小触控区。

| 当前列表与关系 | 行内动作 | 成功后表现 |
| --- | --- | --- |
| 本人关注列表 | 取消关注 | 移出关注列表；若原先互关，对方仍是自己的粉丝 |
| 本人粉丝列表，自己未关注对方 | 回关、移除粉丝 | 回关后显示互相关注，回关按钮替换为取消关注；移除后移出粉丝列表 |
| 本人粉丝列表，互相关注 | 取消关注、移除粉丝 | 取消关注后保留该行，恢复回关；移除后移出该行，保留自己对对方的关注 |

- 取消关注仅解除“我关注对方”；移除粉丝仅解除“对方关注我”，不会连带取消另一方向，不改变拉黑规则。
- 回关沿用普通关注和既有通知规则；取消关注直接执行，不新增确认。移除粉丝需确认，不提供撤销，因为本人不能替对方恢复关注。本次不提供批量操作或重新关注冷却期。
- 关系信息尚未加载或旧响应没有关系字段时，显示既有加载／不可用状态，不把未知当作未关注，也不先显示可能错误的回关动作。

### 移除确认与反馈

- 使用现有确认 Dialog，标题为“移除粉丝「用户名」？”，正文为“移除后，对方将不再关注你。不会通知对方，对方仍可重新关注你。”按钮为“取消”和“移除粉丝”；展示该行的真实用户名称，长名称允许换行。
- 一行内共用提交忙碌状态：保持按钮尺寸，禁用该行其他关系写入操作，阻止重复提交；其余行仍可阅读和操作。Dialog 提交期间按既有规则阻止重复提交和意外关闭。
- 服务端确认成功后再更新列表与关系状态，保留剩余行顺序和滚动位置，最后一项移除后显示对应空状态。同步相关个人主页、列表计数和已缓存关系，避免返回页面后出现旧状态。
- 明确失败保留原项，在该行或列表上下文提供可理解的错误。结果不明时先只读核对服务端状态，不自动重放写入；仍无法确认则说明需要刷新核实，不宣称成功。
- 后到的旧加载结果不能覆盖新操作，切换账号后不能将旧会话响应写入新列表。成功提示使用既有轻反馈，不遮挡下一行操作。
- 键盘与读屏能区分每行操作对象；移除导致触发器消失时，焦点移到下一可用行或列表标题，不能落到页面背景。确认取消后恢复原触发器焦点。

### 消费者验收

- 验证单向／互关的三个动作、本人公开入口和他人列表边界、两页签位置恢复、最后一项删除、失败及结果不明核对。
- 验证连续点击、操作期间刷新、退出或切换账号，确认关系方向、计数和缓存不回退。
- 亮色／黑夜模式下三个动作保持一致；覆盖 Web 键盘与窄容器，以及 Mobile 长用户名、双倍文字缩放、48dp 命中区和系统返回。写入交互测试只在治理规范要求的隔离环境执行。
