# 反馈、无障碍与浮层契约

## 边界

本契约规定 Web 与 Flutter 对异步状态、短暂反馈、模态交互和可访问性的共同语义，不定义后端错误码、请求重试策略或具体组件实现。机器事实源为顶层 `accessibility`、`experiences.feedback` 与 `experiences.overlays`。

## 资源与操作状态

- 首次加载只占据当前资源区域；刷新和加载更多保留已有内容，不能用整页转圈替换可继续阅读的信息。
- 列表与详情首次加载使用保持最终结构的 Skeleton；小范围未知等待与提交按钮使用 Spinner。减少动态效果时 Skeleton 保持静态，不脉冲。
- 空内容与无搜索结果是不同状态。空状态只有在动作真实可执行时才展示行动入口。
- 阻塞当前任务的错误留在页面、区块或表单上下文，并说明下一步；只有确认可安全重复的操作才提供重试。
- Mutation pending 必须阻止同一触发器重复提交。成功或失败后，同一个动作从按钮到反馈保持同一动词。
- Toggle pending 保持提交前的 tone 并显示同色加载指示，不能先闪回未选中态；点赞、收藏、主题帖订阅和普通 Toggle 的色彩与填充规则由图标控件契约拥有。
- Web toast 与 Flutter snackbar 只承载短暂确认。权限变化、保存失败、内容状态等关键结果必须同时在原上下文可见。
- 主题切换是即时界面偏好，不显示成功 toast 或 snackbar；切换控件自身的选中状态就是确认。主题变化不得引入装饰性全屏过渡，减少动态效果下必须同样完整可用。

## 无障碍

- 普通文字、大文字和非文字界面分别满足契约中的最低对比度；状态不能只靠颜色表达。
- 二态按钮同时使用填充/描边变化和平台状态语义：Web 提供稳定名称与 `aria-pressed`，Flutter 提供稳定名称与 toggled 语义；无法改变图形的普通 Toggle 必须补充可见状态文字，不能只改变颜色。
- 键盘焦点始终可见；独立图标控件提供语义名称，装饰图标退出读屏顺序。
- 异步进度默认礼貌播报，只有确实紧急的信息才打断当前朗读。
- Web 尊重浏览器缩放、系统颜色偏好与减少动态效果；Flutter 保留系统颜色偏好、文字缩放、安全区和系统返回。解析后的主题需要同步到浏览器或系统原生控件，不能仅改变应用内容区域。

## 浮层

- Sticky、应用框架、悬浮操作、菜单、模态、Tooltip、模态内二级浮层和全局进度使用中央语义层级，不在业务代码中竞争任意数值。
- 模态阻断背景交互，提供可见关闭入口，退出后恢复触发位置；遮罩点击不能成为唯一退出方式。
- Web 阴影、遮罩与层级由生成 CSS Token 提供。Flutter 使用 flat、floating、popup 三种 elevation 角色；平台原生动画可以不同。
- 图片查看器的高遮蔽背景和手势仍由图片契约拥有，不被普通模态规则覆盖。
- Tooltip 只提供短暂、非必要帮助；Popover 承载锚定的快捷操作、选择或上下文明细；移动端长选项、多操作和上下文明细使用 Sheet；阻断式决定、表单和确认使用 Dialog。
- 可撤销低风险操作直接执行并提供撤销；不可逆或影响他人的操作必须确认。确认标题和按钮明确说出动作，pending 时阻止重复提交和意外关闭。

## 本人关注与粉丝管理

本节应用既有控件、列表和浮层语义，不新增 Token、机器契约字段或组件 API。颜色、字号、间距、圆角、控件状态和排版角色继续消费已发布 Foundation 契约；下述尺寸是本页面的布局目标，不新增全局尺度。接口、权限、能力与关系数据以 Backend 已提交契约为准。

### 入口与紧凑列表

- 本人列表提供“关注／粉丝”同级页签并显示各自计数，从个人主页计数进入时选中对应页签；保留既有地址、深链与返回行为。切换分别保留列表内容和滚动位置，重新进入时沿用平台已有恢复规则。
- Mobile 返回控件与两个计数页签放在同一顶栏，不另占一行重复页面标题。页签、计数与返回各自保留清晰语义；文字缩放时允许顶栏自适应，不截断关键标签或缩小触控区。
- 列表采用紧凑扁平行，无逐行卡框、卡片背景包裹或常驻阴影，不预留固定第二操作行。常规文字大小下 Mobile 行高目标为 64–72dp；行高由内容与触区决定，不使用固定高度裁切内容。
- 头像视觉尺寸为 40dp，昵称采用 body 角色、中等字重，等级采用 caption 角色。昵称和等级构成身份区，不在身份区重复展示右侧已经表达的“已关注／互相关注”状态。Web 使用对应的紧凑尺度，保持桌面信息密度。
- 行末为一个关系动作或状态控件，加独立 ellipsis 菜单触发器。长名可视觉省略但完整名称须进入语义；大字体和窄容器允许自然增高或必要换行，不能溢出、遮住动作或压缩身份与触区。Mobile 所有可点击区域至少 48×48dp，40dp 头像的导航命中区同样满足此下限。
- 头像与昵称进入用户主页，操作区独立响应，点击按钮或菜单不触发行导航。菜单触发器提供“对「用户名」的更多操作”等明确名称。
- 管理能力只在当前登录用户自己的列表出现，通过公开个人主页路径进入本人列表也适用；浏览他人列表保持已有行为。

### 行末动作与统一菜单

- 未关注时，“关注／回关”是主按钮，消费现有 primary 控件与语义色；已关注时显示浅底的“已关注／互相关注”状态控件，消费既有中性表面与控件状态。控件不使用危险色，也不要求所有动作统一成描边按钮；同角色的尺寸、圆角、排版和交互反馈保持一致。
- “已关注／互相关注”状态控件与 ellipsis 打开同一份菜单，状态控件本身不直接取消关注；未关注的主按钮直接执行关注或回关。关系状态由可见文字与可访问性名称共同表达，不只依赖颜色。
- Mobile 使用带目标用户身份、拖柄和明确关闭入口的底部 Sheet，保留安全区、系统返回和大字体滚动。Web 使用锚定触发器的 Dropdown，提供键盘打开、方向键移动、Escape 关闭、可见焦点与关闭后焦点返回；不把桌面菜单替换为移动底部 Sheet。
- 菜单以同一份实时关系状态生成，与当前选中的页签无关。菜单顺序及可用条件如下：

| 菜单项 | 显示与执行条件 |
| --- | --- |
| 私聊 | 既有账号能力允许私聊时提供，沿用原消息入口与权限处理 |
| 取消关注 | 自己已经关注对方时提供 |
| 移除粉丝 | 对方正在关注自己时提供；互关用户在关注和粉丝两个页签内都可移除 |
| 拉黑 | 复用既有拉黑能力与服务端权限，不改变后端关系语义 |
| 举报 | 复用既有用户举报入口与流程 |

- 菜单项保持中性呈现；危险强调只放在移除粉丝和拉黑确认的提交按钮。先关闭菜单，再进入私聊、举报、确认或写入流程，不能叠加菜单与确认浮层；关闭动画或异步间隙后仍须核验页面、目标用户和会话有效。
- 菜单打开期间关系状态变化时，以最新状态决定可用项；触发写入前再次检查共享忙碌状态与当前条件，不能用菜单打开时的旧快照绕过行锁。

### 关系方向与结果

| 操作与当前关系 | 服务端确认后的表现 |
| --- | --- |
| 关注／回关 | 建立“我关注对方”；对方已关注我时显示互相关注，沿用普通关注通知 |
| 取消关注 | 只解除“我关注对方”；关注页签移出该行，粉丝页签保留该行并恢复回关 |
| 移除粉丝 | 只解除“对方关注我”；粉丝页签移出该行，关注页签保留仍关注的用户并改为已关注 |
| 拉黑 | 按服务端可见性刷新列表与计数，不将拉黑描述或实现为自动删除两条关注关系 |

- 互关的另一方向必须保留；移除粉丝不通知对方，对方仍可重新关注。不提供撤销，因为本人不能替对方恢复关注；本次不提供批量操作或重新关注冷却期。
- 取消关注直接执行，不新增确认。移除粉丝和拉黑均复用既有确认 Dialog；移除标题为“移除粉丝「用户名」？”，正文为“移除后，对方将不再关注你。不会通知对方，对方仍可重新关注你。”按钮为“取消”和“移除粉丝”。拉黑确认明确其影响，不能承诺不存在的关注关系删除。
- 关系尚未加载或旧响应没有关系字段时显示既有加载／不可用状态，不把未知当作未关注，也不先显示可能错误的回关动作。

### 异步反馈、会话与焦点

- 同一会话与目标用户共享写入锁，覆盖本人列表的两页签、重复行、状态按钮、ellipsis 和确认框。开始提交即同步阻止重复调用；其余用户的行仍可操作。控件忙碌时保持尺寸，不能因局部浮层重建或关闭而解除仍在进行的共享锁。
- 确认框消费共享 pending；提交期间阻止重复提交、遮罩关闭和系统返回等意外关闭。菜单先退出，确认框再接管焦点；取消后返回原行的可用触发器。
- 服务端确认成功后再更新关系与列表，同步相关个人主页、列表计数和缓存；保持剩余行顺序和滚动位置，最后一项移除后显示对应空状态。拉黑后的行与计数服从服务端刷新结果，不伪造取消关注或移除成功。
- 明确失败保留原项，在行或列表上下文提供可理解错误。请求结果不明时先只读核对服务端状态，不自动重放写入；仍无法确认时保留待核实状态和刷新核实入口，阻止该目标继续写入，不宣称成功。
- 后到的旧加载结果不能覆盖新操作；退出或切换账号后，旧会话的响应、提示、菜单与确认不得写入或触发新会话的界面。仍需操作时由新会话重新加载并建立状态。
- 键盘与读屏能区分每行操作对象及关系状态。操作导致触发器消失时，焦点移到下一可用行或列表标题，不能落到页面背景；短暂成功反馈使用既有轻反馈，不遮挡下一行操作。

### 消费者验收

- 验证本人公开入口与他人列表边界、两个页签的计数和位置恢复、单向与互关状态，以及互关时两个页签均可取消关注或移除粉丝。
- 验证主按钮、状态按钮和 ellipsis 的一致映射，私聊能力开关、举报复用、菜单先关闭再进入下一流程，以及拉黑后的服务端可见性刷新。
- 验证最后一项移除、明确失败、结果不明后的只读核对、本人列表跨页签及所有列表触发入口的共享锁、连续点击、操作期间刷新及退出／切换账号，确认关系方向、计数和缓存不回退。
- 亮色／黑夜模式下保持同角色一致；Web 覆盖鼠标、键盘、焦点返回和窄容器；Mobile 覆盖返回与计数页签同栏、40dp 头像、常规 64–72dp 行高、长昵称完整语义、双倍文字缩放、自适应增高、48dp 命中区、Sheet 身份／拖柄／关闭入口和系统返回。
- 写入交互测试只在治理规范要求的隔离环境执行；线上自动化验收只读，文档检查不能替代消费者界面与真机验收。
