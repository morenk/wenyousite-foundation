# 跨端图片呈现契约

## 边界

本契约规定用户在 Web 与 Flutter 看到同一种图片时应获得的共同语义，不规定上传接口、对象存储 key、派生图命名或业务页面的固定像素。媒体 URL、尺寸、处理状态和可用派生版本由后端生产者契约提供；客户端只能消费显式字段，不自行拼接或猜测 URL。

## 内容角色

| 角色 | 默认适配 | 是否允许裁切 | 查看完整来源 |
| --- | --- | --- | --- |
| 头像 | cover、圆形 | 允许 | 不要求 |
| 封面 | cover、圆角 | 允许 | 可交互时必须 |
| 正文图片 | contain、圆角 | 禁止 | 必须 |
| 画廊缩略图 | cover、圆角 | 允许 | 必须 |
| 收藏表情 | contain、内容形状 | 禁止 | 按场景可选 |

裁切只属于明确的预览语境。用户进入大图查看后必须回到完整来源，不能继续沿用封面或缩略图的裁切框；正文中的长图、截图和含文字图片不得为了列表整齐丢失信息。

## 布局与状态

- 服务端提供宽高时，在图片请求前按真实比例预留空间；未知尺寸使用角色占位而非任意猜测原图比例。
- 加载、处理中、失败、受限和敏感内容都保留原有上下文、比例和可执行下一步。状态由图标/文字/操作共同表达，不只改变颜色。
- 图片失败不能让标题、说明或消息正文一起消失。可安全重试时提供重试；无权限或敏感内容要求确认时提供明确揭示操作。
- 头像可降级为统一占位；正文图和附件不能伪装成头像式字母圆点。
- 动图不影响布局尺寸；进入可见区域前不抢占带宽。减少动态效果下不得把播放作为理解内容的唯一方式。

## 可访问性

- 有内容意义的图片使用所在上下文生成的简短替代文本，不使用文件名、对象 key 或“图片”作为唯一名称。
- 纯装饰图使用空替代文本并退出读屏顺序；可点击图片的查看动作必须有独立可访问名称。
- 不在替代文本里重复旁边已经可见的标题、作者和序号；多图需说明当前位置。
- 放大查看器保留关闭出口、焦点/系统返回和缩放后的平移边界，不能把核心信息锁在手势里。

## 平台映射

Web 用模态 lightbox，支持关闭按钮、Esc、遮罩关闭、适应屏幕、原始尺寸、滚轮和显式缩放控件。Flutter 用全屏路由，支持应用返回、系统返回、双击/捏合缩放和平移；只有未放大时才响应下滑关闭。两端不追求同一动画或像素，只保证完整查看、退出和状态语义一致。

具体角色、状态及平台动作的机器事实源为 `contracts/foundation.v1.json` 的 `experiences.images`。
